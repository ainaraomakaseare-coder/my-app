# Implementation Plan: おもいでバインダー Community + TestFlight

## Overview

既存のSupabase版「おもいでバインダー」を、招待制コミュニティの自己紹介一覧と「友達を覚えたかな」クイズに広げる。写真から名前、共有された特徴・エピソードから人を当て、覚えた人数とコミュニティ内ランキングを表示する。画面はiPhoneを主役に整理し、CapacitorとGitHub ActionsでTestFlightへ渡せるビルド経路を用意する。

## Architecture Decisions

- 既存の`omoide.html`とSupabase projectをデータソースとして使い、古いroom/passwordデータを維持する。
- クイズの問いはコミュニティが登録した情報から決定論的に作る。AI呼び出しや継続課金は追加しない。
- 4択は共有されている同種の情報だけから選び、条件を満たすダミーが揃わない問題は出さない。正解位置を毎回シャッフルする。
- 公開項目はクイズと通常画面で同じ判定を使う。既存のSupabase/RLS構成がアプリ外の直接参照をどこまで制限するかは別途確認し、必要なSQL変更を手順化する。
- スコアは匿名Supabase user IDとroom IDで保存し、同じインストールで個人を識別する。ランキング表示名は利用者が指定する。
- TestFlight用Bundle IDは既存の`com.hiroyaapps.omoidewiki`と分け、`com.hiroyaapps.omoidebinder`を仮案とする。App Store Connectでの登録・署名はこの作業に含めず、必要な手順をREADMEに残す。

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| 現行DB schema/RLSがrepo内に無い | 公開項目やランキング保存が本番で失敗する | 既存テーブルを壊さない追加SQLを作り、適用対象とRLSをREADMEに明記 |
| 旧共有合言葉には参加権限の区別がない | 間違えた招待を取り消せない | 追加SQLで管理者・参加者を分離。退出と招待更新を原子的に実行。一括登録は全参加者向け |
| 旧RLSと写真Storageは招待制のサーバー側境界ではない | 退出後も直接取得される | 追加SQLで会員チェックを必須化しPrivate Storageへ移行。項目別秘匿は未対応 |
| TestFlightの証明書/Bundle IDが未確認 | iOS uploadが完了しない | コードとworkflowを整え、Apple管理画面で必要な操作を具体的に残す |
| 公開プロフィールへの同意手段が無い | 追加者が選んだ情報が即時表示される | TestFlight版の共有範囲を招待ルームに限定し、投稿者が公開項目を選択する旨をUIに表示 |

## 追加: 管理者による参加者の退出（2026-10-05）

管理者が参加アカウントを退出させ、同じ処理で招待コードを再発行する。プロフィールの削除とは別の操作。匿名認証は既存セッションを再利用する。参加者・管理者の権限、退出済み状態をDBで管理し、人物・所属ノート・ランキング・写真の取得に会員チェックを適用する。新規作成者が管理者となり、既存ルームの管理者はSQL Editorで明示指定する（先着者による乗っ取りを防ぐ）。

- [x] Task 6: 参加・管理者・退出・招待更新RPCとRLS、写真のPrivate化用移行SQL
- [x] Task 7: 参加ゲートと参加者管理画面、退出時の表示・キャッシュ消去
- [x] Task 8: ローカルDBで権限・旧招待拒否・他ルーム隔離を検証し、移行手順を更新

本番DBには未適用。既存ルームは管理者割当までロックされる。参加済み端末に取得済みの内容は回収できない。項目単位のDB非公開と永続アカウント復旧は別途対応が必要。

### 追加: 招待流出時の参加受付停止

- [x] Task 9: 管理者限定の参加受付停止・再開RPC。停止と招待失効を同時実行し、再開時は新コードを発行。停止中の退出/招待更新/移行再適用で受付が再開しない。
- [x] Task 10: 管理画面の状態表示・確認・通信失敗時の再取得。DB/DOMのローカル検証15テスト通過（親テストを含む）。本番未適用。
