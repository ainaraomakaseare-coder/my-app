## 4. 動画づくり（tools/video）

使い方の詳細は `tools/video/README.md`。

### 環境（本人のPC特有）
- **Windows on ARM（Snapdragon X Plus）**。Node は arm64 ネイティブ
- ffmpeg：winget の Gyan.FFmpeg（x64 をエミュレーション実行）。場所はスクリプトに書いてある（環境変数 `FFMPEG` で差し替えられる）
- **ffmpeg 内蔵の whisper は使わない**（遅いうえに文字化けした）。文字起こしは Node の transformers.js（`onnx-community/whisper-large-v3-turbo`、エンコーダ q8・デコーダ q4）。モデルは初回だけ `models/hf` にダウンロード（元の `video-tools\models\hf` に保存済み）
- Python は入っていない
- フォントは作業フォルダに `YuGothB.ttc` を写して使う（`C:` の `:` が ffmpeg のフィルタとぶつかるため）
- シェルのヒアドキュメントで固まったことがある。ファイルは Edit/Write ツールで書くのが確実

### 道具
| コマンド | 役割 |
|---|---|
| `node segments.mjs <動画> <出力.json>` | 無音で区切って、区間ごとに文字起こし。**言い直しがどこか分かる**。これで使う区間を決める |
| `node transcribe.mjs <動画> [出力] [--limit 秒]` | 全体をまとめて文字起こし（.srt/.json） |
| `node make-video.mjs <設定.json>` | 設定どおりに縦型動画を書き出す。`--cards` でカードだけ作って確認 |

設定の例：`tools/video/examples/day33.json`（顔＋一覧カード）、`day34.json`（顔＋画像カード）、`day35.json`（画面録画のクリップ＋ぼかし）

### 設定の書き方（要点）
- `crop`：顔の録画（1920x1280）から縦 9:16 に切り抜く位置。顔の位置で x を決める（DAY33:580、DAY34:540、DAY35:520）
- `segments`：使う区間（元の秒）。`lines` は `[元の秒, 字幕]`。`show` は `face` かカードid。`tel` は赤い大テロップ。`joined:true` は直前と音がつながっている（見せるものだけ切り替える）
- `cards`：`shot`（画像。`box` で枠）、`list`（文字の一覧）、`clip`（画面録画。`from/to/speed`、`blur: [[x,y,w,h,(開始秒,終了秒)], …]`）
- 結果カードは、テイクの間の**無音の2〜3秒**に置くと読む時間が取れる。次のテイクの声が入らないよう、区間は次に話し始める前で終える

### 本人に言われた編集ルール（守ること）
- **最後のテイクが正**。言い直しの最後のテイクを、**途中を切らずに**使う（間も残す）
- 切れ目は**話し終わり 0.4 秒・言い始め 0.2 秒の余白**（既定値）。早く切るとぶつ切りに聞こえる
- **字幕は実際に話した言葉**に合わせる（台本と違う言い方をしたら、そちらを汲み取る）。文字起こしの聞き間違いだけ直す
- **専門用語を避ける**（「TestFlight」→「iPhoneでテスト中のアプリ」）。冒頭に赤字で専門用語を出さない
- **友達の写真・名前はぼかす**（本人の名字「清水」は出してよい）
- カード番号・取引ID・APIキー・メールアドレスは隠す
- 書き出したら `segments.mjs` で聞き直し、別の人の声や次のテイクの頭が混ざっていないか確かめる
- 画面の細かい文字は、**要る所だけ切り出して拡大**しないと読めない
- TikTok の基準値から：**50秒以内**に収める、**冒頭2秒で完成したアプリを実際に使っている画面**を見せる、「使っている・できた」回を増やす（`docs/research/TIKTOK_BASELINE_2026-09-29.md`。50秒以下は3本だけなので仮説）

## 6. 予約の手順（Claude がブラウザでやる）

1. 本人に投稿卓へログインしてもらう（**合言葉は本人**）
2. ページ上の JS で `api('/api/upload-url', {method:'POST', body:{contentType:'video/mp4', size}})` → 署名付きURLを受け取る
3. PC から `curl -X PUT -H "Content-Type: video/mp4" -H "x-upsert: true" --data-binary @動画 <署名付きURL>`（200 なら成功）
4. ページ上で：運用アカウントを選ぶ →「投稿を作る」→ まとめて貼る欄に投稿文 →「SNSごとに振り分ける」→ 管理用タイトル・日時（`when` に `2026-10-01T19:00` の形）→ `uploaded = {path, kind:'video', bytes}` → 投稿先のチェック
5. `collect('scheduled')` の中身（投稿先の数・動画・日時・各本文）を確かめてから「この日時に予約する」
6. `api('/api/posts')` で、その投稿が `scheduled`・各SNSが `queued` になったか確認
- **画面は定期的に描き直されて、投稿先のチェックが外れることがある**。押す直前にもう一度チェックする
- 「連携が切れています」で断られたら、連携設定の赤字の理由を見る。つなぎ直しは本人が各SNSの画面でやる

### コマンドで予約する（おすすめ）

ブラウザのページで JS を走らせる代わりに、1コマンドで予約できる（`scripts/schedule-post.js`）。

```
node scripts/schedule-post.js --to x [--to threads ...] --text-file <本文.txt> [--image <画像/動画>] (--at 2026-10-09T17:30 | --now) [--title <管理用タイトル>] [--group <運用アカウントのid か 名前の一部>] [--yes] [--force]
```

- 合鍵は環境変数 `TOUKOUTAKU_TOKEN`、または `%USERPROFILE%\.toukoutaku\token`（1行）に置く。**値はここにもチャットにも書かない**
- 先に本人が Vercel の環境変数に `POST_CLI_TOKEN`（32文字以上）を入れて再デプロイしておく。同じ値を PC 側に置く
- 合鍵で通るのは「画像・動画を置く」「一覧を見る」「`scheduled` の新規作成」だけ。更新・削除・再実行・今すぐ投稿・受け渡しは、ログインした本人の操作のまま
- 内容の確認（投稿先・日時・本文・X の長さ）を出して `y` を待つ。本人が「投稿して」と言ったあとに `--yes` を付ける
- 24時間以内に同じ本文の予約があると止まる（終了コード 2）。意図的なら `--force`
- 最後に一覧を読み直して、`scheduled`・各SNSが `queued` かまで確かめて表示する
