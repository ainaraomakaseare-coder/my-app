# このリポジトリについて

「AIアプリ開発初心者が30日で30アプリ作る」企画の**管理リポジトリ**です。コードは入っていません。資料・進捗・日次ログだけを置きます。

アプリはひとつずつ別のリポジトリに作ります。**作業を始める前に `docs/progress.md` を読んでください。** その日のアプリ・新しい挑戦・対応するリポジトリがそこにあります。企画の全体像は `docs/handoff.md` です。

この企画は「30個作った」で終わりではなく、初心者が毎日ひとつ新しい開発スキルを身につけていく過程そのものが成果物です。動画で発信するため、成功だけでなくエラー・失敗・設定ミスも記録に残します。

## 1日の進め方

1. アプリ用のリポジトリを新しく作る（`dayNN-アプリ名`）
2. `docs/templates/app-repo-CLAUDE.md` を、そのリポジトリの `CLAUDE.md` として置く
3. **このリポジトリ**の `docs/logs/TEMPLATE.md` をコピーして `docs/logs/dayNN.md` を作り、**開始時刻を書いてから**開発に入る
4. 終わったら `dayNN.md` を埋め、`docs/progress.md` の表と累計を更新する

ログは必ずこのリポジトリに書きます。アプリ側のリポジトリには置かないでください。30日分を最終日に集計するので、散らばると集められません。

## 開発を手伝うときのお願い

1. **要件が曖昧なら先に質問する。** いきなりコードを書き始めない。
2. **大型アプリは機能を分割する。** 一度に全部指示すると設計が重くなり、生成も長引く。
3. **その日の「新しい学び」を意識する。** 各DAYには必ず初挑戦のテーマがある。そこが動画の芯になるので、そこだけは省略しない。
4. **初心者でも分かる言葉で説明する。** 専門用語を使うときは一度かみ砕く。
5. **エラーやつまずきもログに残す。** うまくいった手順だけ書かない。つまずきの方が動画になる。
6. **AI実稼働時間を可能な範囲で記録する。**
7. **ユーザーの入力待ち・回答待ちの時間はAI実稼働時間に含めない。**
8. **費用が発生する場合は着手前に伝える。** API課金・有料プラン・ドメインなど。
9. **APIキーや秘密情報をコードやGitHubに出さない。** 環境変数と `.gitignore` を使い、ハードコードしない。
10. **開発終了時にDAY RESULTを作る。** 下記フォーマットで。

### 数字を作らない

AI実稼働時間や費用が正確に取れなかった場合、**推測して数字を埋めない**。「正確な計測不可」と書く。最終日に30日分を集計するので、混ざった数字は後で取り返せません。

## DAY RESULT フォーマット

動画の最後に出す形式です。ログの末尾にもこの形で残します。

```
DAY ○ RESULT
アプリ：○○
人間：○h○m
AI：○h○m
費用：○円
今日できるようになったこと
・○○
・○○
つまずいたこと
・○○
・○○
あと○ apps
```

## 開発終了時にもうひとつ

DAY RESULT と一緒に「**今日の動画で使えるポイント**」を3つ程度あげてください。意外な失敗、新しい発見、作業時間が縮んだ場面、AIの限界が見えた場面、初心者が勘違いしやすい点――このあたりから拾います。
