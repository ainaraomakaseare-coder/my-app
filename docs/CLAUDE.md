# このリポジトリについて

「AIアプリ開発初心者が30日で30アプリ作る」企画の**管理リポジトリ**です。コードは入っていません。資料・進捗・日次ログだけを置きます。

アプリの置き場所はいま2つの方式が混ざっています（DAY3〜6 は `my-app/apps/`、DAY7 は別リポジトリ）。
どちらに寄せるかは未決です。**作業を始める前に `docs/progress.md` の「置き場所の決めごと」を読んでください。** その日のアプリ・新しい挑戦・対応するリポジトリがそこにあります。企画の全体像は `docs/handoff.md` です。

この企画は「30個作った」で終わりではなく、初心者が毎日ひとつ新しい開発スキルを身につけていく過程そのものが成果物です。動画で発信するため、成功だけでなくエラー・失敗・設定ミスも記録に残します。

## 1日の進め方

1. アプリの置き場所を用意する。`my-app/apps/dayNN-アプリ名/` を作るか、別リポジトリ `dayNN-アプリ名` を作る（別リポジトリはAIから作れないので人が GitHub の画面で作る）
2. 別リポジトリにした場合は `docs/templates/app-repo/` の中身をその直下にコピーする。`CLAUDE.md` と、時間を自動で記録する `.claude/` が入っている。`my-app` の中に作る場合は既にある
3. **このリポジトリ**の `docs/logs/TEMPLATE.md` をコピーして `docs/logs/dayNN.md` を作り、**開始時刻を書いてから**開発に入る
4. 終わったら、アプリ側で `node .claude/hooks/timelog.js report` を実行して出た数字を `dayNN.md` に書き写し、`docs/progress.md` の表と累計を更新する

## 時間の記録について

アプリ側のリポジトリに `.claude/` を置くと、セッション開始・あなたの送信・応答完了の時刻が
`.claude/time/YYYY-MM-DD.jsonl` に自動で貯まります。`report` はこれを集計して、実時間と
「AI稼働（近似）」を出します。

AI稼働は**送信してから応答し終えるまでの合計**で、あなたが入力・検討している時間は入りません。
企画の定義（ユーザーの入力待ち・回答待ちを含めない）と一致します。ただし Claude Code は内部の
計算時間を出さないため応答時間の合計＝近似値です。ログには「近似（応答時間の合計）」と書き、
実際より大きい値だと分かるようにしてください。

人間の作業時間は実時間そのままではありません。休憩や別作業を引いた値を自分で記入します。
生データ（`.claude/time/`）は gitignore してあります。集計だけをこのリポジトリに書き写してください。

ログは必ず `docs/logs/` に書きます。アプリのフォルダや別リポジトリには置かないでください。30日分を最終日に集計するので、散らばると集められません。

## 開発を手伝うときのお願い

1. **要件が曖昧なら先に質問する。** いきなりコードを書き始めない。
2. **大型アプリは機能を分割する。** 一度に全部指示すると設計が重くなり、生成も長引く。
3. **その日の「新しい学び」を意識する。** 各DAYには必ず初挑戦のテーマがある。そこが動画の芯になるので、そこだけは省略しない。
4. **初心者でも分かる言葉で説明する。** 専門用語を使うときは一度かみ砕く。
5. **エラーやつまずきもログに残す。** うまくいった手順だけ書かない。つまずきの方が動画になる。
6. **AI実稼働時間を可能な範囲で記録する。**
7. **ユーザーの入力待ち・回答待ちの時間はAI実稼働時間に含めない。**
8. **費用が発生する場合は着手前に伝える。** API課金・有料プラン・ドメインなど。
9. **APIキーや秘密情報をコードやGitHubに出さない。** 環境変数と `.gitignore` を使い、ハードコードしない。
10. **開発終了時にDAY RESULTを作る。** 下記フォーマットで。

### 数字を作らない

AI実稼働時間や費用が正確に取れなかった場合、**推測して数字を埋めない**。「正確な計測不可」と書く。最終日に30日分を集計するので、混ざった数字は後で取り返せません。

## DAY RESULT フォーマット

動画の最後に出す形式です。ログの末尾にもこの形で残します。

```
DAY ○ RESULT
アプリ：○○
人間：○h○m
AI：○h○m
費用：○円
作ったアカウント：○○
今日できるようになったこと
・○○
・○○
つまずいたこと
・○○
・○○
あと○ apps
```

## 作ったアカウント

その日に新しく登録したサービスがあれば、ログと DAY RESULT に残します。サービス名・無料か有料か・
何に使ったか、の3つだけです。30日で何個のサービスに登録したかは最終日に出したい数字であり、
「アプリを作るには何に登録することになるのか」は初心者がいちばん知りたい情報でもあります。

**パスワード・APIキー・接続情報は書かないでください。** 書くのはサービス名と用途だけです。
登録していない日は「なし」と書きます。

## 開発終了時にもうひとつ

DAY RESULT と一緒に「**今日の動画で使えるポイント**」を3つ程度あげてください。意外な失敗、新しい発見、作業時間が縮んだ場面、AIの限界が見えた場面、初心者が勘違いしやすい点――このあたりから拾います。
