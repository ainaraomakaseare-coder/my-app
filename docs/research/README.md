# 分析部隊 — 伸びている投稿を集めて、比べて、次の企画を決める

## 何のためか

自分のアカウントの数字は、まだ小さすぎて比べられない（DAY14：フォロワー0〜12人。
1人増えると「50%成長」になり、差のほとんどは偶然）。
そこで、**同じジャンルで伸びている投稿を集めて、作りを比べる**ほうから改善点を探す。

## 3つの役

| 役 | 誰がやるか | 入力 | 出力 |
|---|---|---|---|
| ① 収集 | YouTube：アプリ（「のび」画面 →「集める」）<br>TikTok・X・Instagram・Threads：Claude in Chrome（`docs/research/CHROME_COLLECT.md`） | 検索する言葉 | 1本ごとの記録（JSON） |
| （点検） | `scripts/benchmark-intake.js`（機械） | ①の JSON | `research/<genre>/<date>.json` |
| ② 分析 | サブエージェント `trend-analyst`（Sonnet） | 点検済みの記録と、自分の投稿 | `research/<genre>/<date>-analysis.md` |
| ③ 企画 | この会話（Opus）がスキル `plan-from-analysis` で決める | 分析の結果 | `research/<genre>/<date>-plan.md` |

**分ける理由**
- ①はページをたくさん読むので中身が散らかる。②と混ぜると、裏の取れていない数字が結論に流れ込む
- ①と②のあいだで、全部の数字に出どころがあるかを**機械で点検**する（`lib/benchmark.js`）。捏造の数字を分析に入れないため
- ③は判断の仕事で、このアプリの制約（嘘を書かない・お金・作れる動画の型）を知っている必要がある。CLAUDE.md の取り決めで、判断は Opus、決まった作業は Sonnet

## 必要な情報

### ① 収集：1本ごとに記録するもの（形は `lib/benchmark.js`）

| 項目 | なぜ要るか |
|---|---|
| URL・SNS・アカウント名 | 元に戻って確かめるため。URL は SNS と一致しないと弾く |
| **フォロワー数** | 「伸びている」を再生数の大きさでなく「のび率＝再生数÷フォロワー数」で見るため |
| 再生・いいね・コメント・保存・シェア | 見えたものだけ。**見えないものは null（0 にしない）** |
| 数字の出どころ（api / screen）と確かめた日 | 嘘の数字を入れないため |
| 投稿日 | 直近30日かどうか |
| 冒頭（hook）：最初の2秒の文字・1行目 | 伸びを一番左右する。分析の一番大事な材料 |
| 題名か1行目、長さ（秒）、型、最後の呼びかけ、ハッシュタグ | 作りの比較 |
| テーマ、コメントの質問（最大3つ） | 需要と供給を見るため |

**「伸びている」の基準**：直近30日、のび率10倍以上。フォロワー10万人未満のアカウントを優先する
（いまの自分たちと比べられる相手にするため）。

### ② 分析：比べる相手として要るもの
- ①の記録（1ジャンル50本くらい）
- 自分の投稿の記録（「のび」画面の数字、作っている型、投稿時刻）

### ③ 企画：決めるのに要るもの
- ②の結果
- 作れるものの範囲：アプリで自動で作れるのは「文字の穴埋め6問の動画」と文章だけ。顔出し・画面収録・声は人手
- 決めごと：ひろや側は本人の実践記録で一人称でよい。転職側は一人称の体験禁止。どちらも出典のない数字・効果の断定は禁止
- 目的：ひろや＝フォロワー／転職＝フォロワーと案件への誘導

## 分からないこと（先に言っておく）
- 他人の投稿の**完走率・視聴時間**は見られない。伸びを一番左右すると言われる数字だが、比べられない
- X・Threads・Instagram の写真投稿は、再生数が出ないことが多い（いいねで代える）
- 画面の数字は丸められている（「1.2万」は12,000として記録する）
- この作業環境（クラウド）からは YouTube・TikTok のページを直接読めない。だから①はアプリと Chrome で行う

## 回し方
1. 「のび」画面で YouTube を集め、「分析用にコピー」→ 会話に貼る。
   続けて「自分の投稿を分析用にコピー」→ 会話に貼る（`research/<genre>/own-<date>.json` として保存する）
2. Claude in Chrome に `CHROME_COLLECT.md` の指示文を貼り、返ってきた JSON を会話に貼る
3. 会話側で `node scripts/benchmark-intake.js` に通して保存する
4. 「分析して」→ `trend-analyst` が②を書く
5. 「企画に落として」→ `plan-from-analysis` で③を書く。**利用者が決めるまで予約はしない**

お金は追加でかからない（YouTube の API は無料枠、Chrome は手元、分析と企画はこの会話の中）。
