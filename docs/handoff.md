# 30日で30アプリ開発企画 引き継ぎ資料

## 1. 企画概要

AIアプリ開発初心者が、30日間で30個のアプリを作るチャレンジ企画。目的は3つ。

1. AIアプリ開発初心者が30日間でどこまで成長できるかを可視化する
2. TikTok / Instagram Reels / YouTube Shorts / X で日々の開発過程を発信し、フォロワーを増やす
3. 将来的にAIアプリ開発コーチング・AI活用支援などの事業につなげる

単に「30個作る」だけではなく、**初心者が毎日1つずつ新しいAI開発スキルを身につけていくストーリー**として設計する。

## 2. 動画・発信の基本方針

毎日の動画には以下をできるだけ入れる。

今日作るアプリ / 今日の新しい挑戦 / 実際の開発画面 / AIへの指示 / つまずいたこと / 解決方法 / 完成アプリ / 今日できるようになったこと / 人間の作業時間 / AIの実稼働時間 / 費用 / 残りアプリ数

成功だけでなく、**エラー・失敗・設定ミス・AIが止まった・PCが落ちた**も積極的にコンテンツにする。

## 3. 動画の基本構成

30〜60秒程度。

| 尺 | 内容 |
|---|---|
| 0〜3秒 | 強いフック。「AIアプリ開発初心者が30日で30アプリ。DAY○。」あるいは「昨日買ったPC、今日買い直しました。」など、その日の一番強い出来事を先に出す |
| 3〜10秒 | 今日作るもの・課題説明 |
| 10〜35秒 | 開発画面（Claude Code / Codex / GitHub / API / DB / エラー / AIとのやり取り）。開発中の音声は基本的に後入れナレーション |
| 35〜50秒 | 完成したアプリを実演 |
| 最後 | DAY RESULT（人間稼働・AI稼働・費用・今日できるようになったこと・つまずいたこと・あと○個） |

## 4. DAY1：くじ引きアプリ

**テーマ**：初めてAIでアプリを作る。

**実施内容**

- Chromebookを購入（64,900円）
- Claude Code（19ドル）
- ChromebookでClaude Codeを使うためLinux環境を構築
- Claude Codeをセットアップ
- くじ引きアプリを作成

**時間**：開始17:00 / 終了20:00 / 人間作業 約2時間30分 / AI作業 約30分

**つまずいたこと**

- ChromebookだったためLinux環境の構築が必要だった
- Linux・ターミナル周りで戸惑った
- PCスペックが低くClaude Codeが何度も落ちた
- Chromebookの画面録画素材を誤って消してしまった

**今日できるようになったこと**

- PCでClaude Codeをセットアップ
- Claude Codeを使ってアプリを作る
- 分からない画面をスクショしてClaudeに見せると状況を理解してもらえる

**動画ストーリー**：「30日で30アプリスタート」→ PC購入 → アプリを作る前にLinux環境構築で苦戦 → Claude Code導入 → くじ引きアプリ完成 →「ただ、このPCを翌日買い直すことになる」

## 5. DAY2：ミリオネアアプリ

**テーマ**：PC買い直し＋Windows環境構築。

Chromebookのスペックが厳しかったため、Windows PCを129,800円で購入。Windows側で Claude Code / Codex / 開発環境 を再セットアップし、ミリオネア風クイズアプリを開発。

**ストーリー**：「昨日買ったPC、今日買い直しました。」→ Chromebook 64,900円 → Claude Codeが何度も落ちた → Windows PC 129,800円購入 → 環境構築をやり直し → ミリオネアを作成 → アプリ自体はかなり早く完成

**学び**：環境構築は大変だが、一度整えばAIによるアプリ生成はかなり速い。

## 6. DAY3：チンチロアプリ

**テーマ**：AIへの指示方法をレベルアップ。

**新しい挑戦**：これまではコマンドプロンプト中心だったが、デスクトップアプリ＋GitHub連携で開発する。さらに、いきなり「アプリを作って」と指示するのではなく、「あなたは要件定義のプロです。まず私にヒアリングしてください」と依頼。AI側から人数・ゲームルール・特殊ルール・画面構成・勝敗条件などを質問してもらう。通常のチンチロではなくルールを少しカスタマイズする。

**動画の切り口**：「AIに『作って』と言うの、今日からやめます。」

**今日できるようになったこと**

- GitHubと連携してデスクトップ環境から開発
- AIに要件定義をさせる
- AIに先に質問させて要件を固める

## 7. DAY4：輸入ブラックジャック

過去に作ったことがあり、さらば青春の光の動画で紹介されたゲームをベースにアプリ化する。

**テーマ**：少し特殊・複雑なゲームルールをAIに理解させて実装する。DAY3で覚えた要件定義を活用する。

**見せたいポイント**：普通のブラックジャックとは違うルール / AIがルールを正しく理解できるか / 勝敗条件などのズレ / 修正指示

## 8. DAY5：ドラマ王アプリ

**テーマ**：外部情報をアプリに取り込む。

これまでのアプリは基本的に自分で用意した情報・ルールを使っていた。DAY5では指定したドラマについて外部から情報を取得し、その情報を使ってクイズを生成する。

ドラマ名を指定 → 外部情報を取得 → 登場人物・ストーリー・出来事等をもとに問題生成 → 10問程度のクイズ → 正解数・ランク表示

**動画の切り口**：「今までのアプリ、データは全部自分で用意してました。今日は初めて外から情報を持ってきます。」

**学び**：アプリの外にある情報を利用する。APIを使うか、他の安全な方法で情報取得するかは開発時に検討する。

## 9. DAY6：人狼アプリ

**テーマ**：初めてアプリを一般公開する。

現在の人狼アプリには「1台のスマホを全員で回して役職を確認するため時間がかかる」という課題がある。これを、各参加者が自分のスマホから同じルームに参加し、自分の役職を自分の端末で確認できるようにする。

**想定機能**：ルーム作成 / 合言葉またはQRコード / 各プレイヤーが参加 / 役職ランダム配布 / 自分の役職だけ確認 / 複数スマホからアクセス

**新しい挑戦**：localhostではなくインターネットに公開。

**動画フック**：「今まで作ったアプリ、実は全部僕しか使えませんでした。」

**学び**：デプロイ / 一般公開 / 複数端末利用

## 10. DAY7：サッカー出欠管理

**テーマ**：初めてデータベースを使う。

**想定機能**：メンバー登録 / 試合・練習日登録 / 出席 / 欠席 / 未回答 / 出席人数表示 / データ保存

**新しい学び**：今まではアプリを閉じると情報が消えるケースが多かった。DAY7では入力した情報が後からも残る状態を作る。Supabase等を候補とする。

## 11. DAY8：大型・草野球チーム管理アプリ

**テーマ**：初めての大型アプリ。

このアプリは既に以前から開発しており、DAY8の1日だけでゼロから作ったものではない。動画上でも「これは1日では終わりませんでした。実は少し前から裏で作ってました。」と正直に出す。

**主な機能**：チーム管理 / 選手管理 / 出欠管理 / 試合管理 / 打撃成績入力 / 打率 / 本塁打 / 各種成績 / ランキング / その他野球チーム運営機能

これまでの小型アプリとは違い、複数機能を1つのサービスとして統合する。

**つまずき候補**：コード生成に時間がかかる / AIに任せて放置したら質問待ちで止まっている / 一度に指示すると設計が重すぎる / 機能を分割して作る必要がある

**DAY RESULT**では通常の項目に加え、開発期間・人間総稼働・AI総稼働・機能数も出したい。

## 12. DAY9：SNS投稿管理アプリ

30日企画で TikTok / Instagram / X / YouTube へ毎日投稿するのが大変なため、SNS投稿をまとめて管理できるアプリを作る。

**想定機能**：投稿文作成 / 投稿予定日時 / SNS選択 / 動画・画像管理 / 投稿済み・未投稿 / SNS API連携

**テーマ**：初めてAPIで別のサービスとつなぐ。初心者向けには API＝「自分のアプリと別のサービスをつなぐ窓口」として説明する。

**想定されるつまずき**：APIキー / 開発者アカウント / OAuth / 権限 / 各SNSで仕様が違う / 料金・無料枠 / API制限

最初から全SNSへの完全自動投稿を目指さず、まず1サービスとの連携でもよい。

## 13. DAY10：Skills

**テーマ**：Claude Code等のSkillsを使ってAI開発の品質を上げる。

ここまであえて普通にAIを使ってきた。DAY10で「AIにも追加能力を持たせられる」ことを紹介する。

**おすすめ企画**：DAY1のくじ引きアプリをSkillsを使って作り直し、Before / After で比較。

**見せたいポイント**：UI品質 / UX / コード品質 / 作業効率 / Before・After

**動画フック**：「AIに作らせればアプリはできます。でも正直、見た目がダサい。」→「今日はAI自体をレベルアップさせます。」

## 14. DAY11以降で入れたいテーマ

Day固定はまだしていない。

**LP作成**：作ったアプリ・サービスを販売するためのLPをAIで作る。テーマは「作る → 公開する → 売る」まで経験する。「あなたはLP制作・セールスコピーのプロです。まずターゲットと悩みをヒアリングしてください」という使い方もする。

**野球期待値計算アプリ**：大量の野球データから必要な情報を正確に取得し、期待値を計算する。テーマは大量データの中から正しい情報を取得すること。単純なAI回答ではなく、CSV / DB / SQL / RAG等を使って条件に合うデータだけ検索する方向を検討。

**オンライン対戦ゲーム**：複数端末間でリアルタイム対戦。最初は○×ゲーム / じゃんけん / チンチロ / ブラックジャックなど簡単なターン制ゲームから。テーマはリアルタイム通信。想定課題は同期 / WebSocket / リアルタイムDB / 切断 / 再接続 / 勝敗管理。中盤以降の大型企画候補。

**iOS / Android提出**：作ったアプリを App Store / Google Play に提出する。テーマはWebアプリからストアアプリへ。想定されるつまずきは Apple Developer / Google Play Console / 審査 / スクリーンショット / プライバシーポリシー / 署名 / ビルド / ストア説明文。iOSとAndroidは別日にしてもよい。

## 15. 今後入れたいつまずき・成長要素

30日間に以下を自然に散らす。

| つまずき | 想定DAY |
|---|---|
| 環境構築 | DAY1 |
| PCスペック不足 | DAY1〜2 |
| AI生成に時間がかかる | 大型アプリ時 |
| AIを放置したら質問待ちで止まっていた | 大型アプリ時 |
| 一般公開が難しい | DAY6 |
| DB接続が難しい | DAY7 |
| APIが難しい | DAY9 |
| UIがダサい | DAY10（Skillsにつなげる） |
| セッション利用上限 | 中盤 |

**セッション利用上限**は「AIなら無限に働くと思っていたら止まった」という動画ネタ。

**モデルの使い分け**：高性能モデルばかり使うとセッション・利用量を消費するため、軽い作業 / 重い設計 / 難しいバグ でモデルを使い分ける。

**Skills**：AI自体の能力を追加して品質改善。

**他サイトのUIを参考にする**：「機能はできたけど見た目がダサい」→ 良いサイトのデザインを参考にAIへ指示。

## 16. 毎日のAI稼働ログ

開発開始時に必ずログを取る。Claude Code / Codex は、ユーザーが入力している時間や回答待ち時間を「AI実稼働時間」に含めない。

記録する項目：開発開始時刻 / 開発終了時刻 / AI実稼働時間 / 人間作業時間 / AI待機時間 / 実施作業 / エラー / つまずき / 今日できるようになったこと / 使用モデル / モデル別作業内容 / API利用 / AI利用料金 / API料金 / その他費用

**AI実稼働時間が正確に取得できない場合、推測して数字を作らない。「正確な計測不可」とする。**

## 19. Claudeへのお願い

`CLAUDE.md` に同じ内容を置いてある。開発を手伝う際は単純にコードを書き始めるのではなく、必要に応じて以下を行う。

1. 要件が曖昧なら先に質問する
2. 大型アプリは機能を分割する
3. その日の「新しい学び」を意識する
4. 初心者でも理解できる言葉で説明する
5. エラーやつまずきもログに残す
6. AI実稼働時間を可能な範囲で記録する
7. ユーザー回答待ち時間はAI実稼働時間に含めない
8. 費用が発生する場合は事前に伝える
9. APIキーや秘密情報をコード・GitHub等へ公開しない
10. 開発終了時にDAY RESULTを作成する

また、動画企画として面白くなりそうな**意外な失敗 / 新しい発見 / 作業時間短縮 / AIの限界 / 初心者が勘違いしやすい点**があれば、開発終了時に「今日の動画で使えるポイント」として3つ程度提示する。
