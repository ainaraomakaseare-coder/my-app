### 書くときのルール（引き継ぎから）

1. 本人が後から直した数字を、古いログより優先する
2. 概算には「約」「本人申告」を残す。分からないものは「正確な計測不可」「未確認」
3. 人間時間＋AI時間は「作業時間の合算」。実際に経過した時間とは分ける
4. セッション上限・待ち時間・審査待ちを、AIの作業時間に数えない
5. 機器の購入、契約料、APIへの入金、APIの実際の消費額、参考の換算額を分ける
6. サービスを使っただけで「新しくアカウントを作った」と書かない
7. TestFlightのテスト配信とApp Storeの一般公開を分ける。テストでの成功と実際に使って成功したことも分ける
8. **DAYは企画上の番号。** 同じアプリの改良回やツールを試した回も含む。「30個の別々のアプリを毎日1個ずつ完成させた」とは書かない

### 無料エリア

**はじめに**
- この記事で手に入るもの（有料部分の目次と特典を先に見せる）

**第2章 頼み方を変えたら、アプリが化けた（段階2〜4）**

| 売上上位20%の実用ノウハウ系の平均価格は **1,842円**、読み物系は983円 | note公式の約30万件分析 | 読み物（体験記）ではなく**実用ノウハウ**として出す。1,980〜2,980円は相場の範囲内 |

| 無料部分＝悩みの整理・筆者の背景・全体像／有料部分＝手順・テンプレート・データ・チェックリスト | 各種の書き方ガイド | 初稿の区切り方は合っている。有料部分の「持ち帰れる物」を増やす |
| 1記事を長く売り続け、**初月の売上は全体の1割未満**。SNS・YouTubeから流れてくる導線で売れ続ける | 「1記事noteの人」の運用記録 | 記事を量産しない。**1本を追記・更新し続け**、動画とXから流す |
| 初回は安く出して実績を作り、段階的に値上げ | 価格設定ガイド | 初稿の「先着20部 → 値上げ」は正しい。値上げを複数段にする |
| 非エンジニアでも技術系noteは売れる。理由は技術力ではなく「説明力」 | 非エンジニアの収益化体験記 | 「コードを書けない人が、書けない人に向けて説明する」を前面に |
