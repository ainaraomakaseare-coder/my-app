## エラー・つまずき

1. **アプリが指定リポジトリに無かった。** 作業先として指定された `my-app` の中身は
   DAY3 のチンチロアプリで、サッカー出欠アプリは別リポジトリ `day07-soccer-attendance` にあった。
   DAY7 で置き場所を分けた結果、指定と実体がずれていた。
2. **`supabase.com` / `netlify.com` に到達できない。** DAY7 と同じ。料金を公式で確認できず。
3. **Playwright のブラウザ版数が合わない。** DAY7 と同じ。環境には 1194 が入っているのに
   インストール済みの Playwright は別の版を探しに行く。
4. **`schema.sql` が Supabase 固有のロールを前提にしていた。** `anon` と `authenticated` に対する
   `revoke` があるが、手元の PostgreSQL にはそのロールが無く、`role "anon" does not exist` で止まる。
   **README にその手順が書かれていない。**
5. **JavaScript の `String.replace` が `schema.sql` を壊した。** 置換後の文字列に含まれる `$$`
   （PostgreSQL の関数本体の囲み）を、`replace` が「エスケープされた `$`」と解釈して `$` に縮めてしまう。
   結果 `as $` という壊れた SQL が生成され、`syntax error at or near "$"` になった。
6. **作業中にコンテナが再起動し、PostgreSQL が落ちた。** データは残っていたがサーバーは停止していた。
   時間計測の連続性も切れた。
7. **画面の作り直しでテストが赤くなった。** 種別を示すクラスをバッジからカードへ移した結果、
   テストが見ていた `.badge.match` が消えた。
8. **`npm run build` の公開リストに `js/auth.js` を足し忘れた。**
   **これは公開して初めて「ログインだけ動かない」と分かる種類の失敗。**手元では気づけない。
9. **要件が途中でひっくり返った。** 画面を作り始めた後で「今のままだと世間に出せるものではない、
   要件定義しなおしたい」となり、作りかけを捨てて要件定義からやり直した。

## 解決方法

1. → 利用可能なリポジトリを一覧し、`day07-soccer-attendance` を見つけてセッションに追加。
   作業前に「実体がどこにあるか」を確かめる必要があった。
2. → 数値は知識から示したうえで、**公式ページでの確認を本人に依頼**。推測で確定させない。
3. → DAY7 と同じく `chromium.launch({ executablePath })` で環境内の Chromium を直接指定。
4. → `create role anon nologin; create role authenticated nologin;` を手元で先に作った。
   さらにテストが自前で用意するよう `db.test.sql` に組み込み、README にも書いた。
5. → `s.replace(a, b)` をやめ、`s.replace(a, () => b)` と**関数で渡す**形に変更。
   関数形式なら `$` の特別扱いが起きない。壊れた `schema.sql` は `git checkout` で戻してやり直した。
6. → `pg_ctlcluster 16 main start` で立て直し。データベースは無事だった。
7. → バッジに種別のクラスを戻した。**作り直す前にテストが見ているセレクタを洗い出しておいたのに、
   1つ取りこぼしていた**。テストが捕まえた。
8. → `PUBLISH` に足したうえで、**`dist` の HTML が読み込んでいるファイルが実際に `dist` に
   入っているかを機械的に検査する処理**を `build.js` に追加。わざと外して止まることも確認した。
   DAY7 の `.gitignore` 書き漏れと同じ型の失敗なので、仕組みで防ぐ側に倒した。
9. → 作りかけをコミットせずに保持し、`requirements.md` を先に書いて確認を取ってから再開した。

## 設計の判断（動画の芯）

### DAY7 で諦めた Google ログインが、実は通せた

DAY7 では「**LINE の内蔵ブラウザが Google 認証を弾く**（`403: disallowed_useragent`）」を理由に
Google ログインを捨て、個人リンク方式にした。

今回調べ直したところ、**URL の末尾に `?openExternalBrowser=1` を付けると、LINE は内蔵ブラウザを使わず
端末の既定ブラウザ（iPhone は Safari、Android は Chrome）で開く。**内蔵ブラウザを通らないので
Google の制限に当たらない。配布リンクは管理画面が組み立てているので、そこにパラメータを足すだけだった。

**「できない」と判断した理由が、次の日には成り立たなくなっていた。**

### リンクの役割を変えた

| | DAY7 | DAY9 |
|---|---|---|
| リンク | **鍵そのもの**。ずっと有効 | **一度きりの招待状** |
| 本人確認 | リンクを持っていること | Google アカウント |
| 転送されたら | なりすませる | 紐付け済みなら無効 |

DAY7 の README「いま出来ないこと」に書いてあった弱点が、これで消えた。

### 全員のログインを待たない

実装時に決めたこと。**まだログインしていない人の招待リンクは、今までどおり使えるままにした。**
全員が一斉にログインするのを待たずに移行でき、DAY7 のテストも生きたまま残る。
ログインした人から順にリンクが無効化されていく。誰が済んでいるかは管理画面で分かる。

### 色は意味にだけ使う

DAY7 の画面は背景も見出しも緑だった。サッカー＝芝の連想だが、**「出席」の緑がその中に埋もれていた。**
今回は背景を無彩色にし、緑は出席、赤は欠席、濃紺は試合、とだけ決めた。

### 「出席9人」より「あと2人」

試合には11人要る。マネージャーが本当に知りたいのは人数ではなく**足りているかどうか**なので、
試合のカードには「あと ○ 人で11人」を出した。練習には出さない（11人揃える必要がないため）。

## 今日の動画で使えるポイント

1. **「できない」と切り捨てた判断が、2日後にひっくり返った。**
   DAY7 で「LINE の内蔵ブラウザが Google ログインを弾く」から個人リンク方式を選んだ。
   今日調べ直したら、**URLに `?openExternalBrowser=1` を足すだけで回避できた。**
   AI が出した「できません」は、その時点の調査結果でしかない。

2. **公開して初めて分かる失敗を、公開前に捕まえた。**
   ログイン用の `js/auth.js` を作ったのに、**公開ファイルの取り出しリストに足し忘れていた。**
   手元では動く。公開すると**ログインだけが動かない。**
   ビルドを試して気づき、直したうえで「HTMLが読み込んでいるファイルが公開対象に入っているか」を
   自動で検査する処理を足した。DAY7 の `.gitignore` 書き漏れと同じ型で、**2回目は仕組みで潰した。**

3. **要件定義を途中でやり直した。**
   画面を作り始めた後で「今のままだと世間に出せるものではない」となり、作りかけを捨てた。
   そこで**コードから「出せない理由」を挙げた**——`team_config` に `check (id = 1)` と書いてあり、
   構造的に1チームしか入らない。磨きではなく土台の作り直しになる、と分かった。
   **「なんとなくダサい」ではなく、どこがどう出せないかを特定すると、やることが決まる。**

**予備**

- **`$$` が消える。** JavaScript の `replace` は置換文字列の `$$` を `$` と解釈する。
  PostgreSQL の関数は `$$` で囲むので、SQL を機械的に書き換えたら壊れた。
- **README に書いていない前提があった。** `schema.sql` は Supabase 固有のロールを前提にしていて、
  手元の PostgreSQL では動かなかった。「自分の環境では動く」の典型。
