## 実施作業

- 「評価の保存に失敗しました」「天気の手動修正が保存できない」という報告を、`wrangler tail`のログを見ながら診断。当初はWKWebView固有の挙動・CORS・OpenAIキー切れなどを疑ったが、いずれも的外れ（評価・天気の手動修正はOpenAIを一切呼び出さない機能だった）。最終的に`wrangler tail --format json`で`event.response.status`を直接見る形に切り替え、さらに`git log -1`でユーザーの手元のコードが4日前のものだったと判明。`git pull origin main`→`wrangler deploy`で解決した
- 上記の教訓を`CONTEXT.md`に明文化し、診断用に一時追加したログ出力は解決後にすべて削除した
- 動画のサムネイルが縦長のまま表示されていた不具合を修正し、写真と同じグリッドの粒度に揃えた（タイル＋ライトボックス方式に作り直し）
- 宿泊先の表示を、1件だけを表示していた従来の作りから、宿泊カテゴリの予定（Block）を日付順にたどって「何泊目に誰の宿か」を組み立てる方式に変更（同じ宿が続く夜は「1〜6泊目：Aホテル」のように範囲表記）
- 旅行詳細の「総費用」統計カードをタップすると、参加者ごとの支払い合計の内訳が見られるようにした
- 1つの記録（Entry）に複数枚の写真があるとき、ライトボックスを開いたまま矢印ボタン・左右スワイプで前後の写真に移れるようにした
- ホーム画面の「マイ旅行」一覧に、誰と一緒か・年・旅行区分（サークルの友達／バイト先／家族などの自由入力）で絞り込むプルダウンを追加。旅行区分は新規・編集フォームに自由入力欄として追加し、DB（`trips.trip_type`、v14マイグレーション）にも保存できるようにした

## エラー・つまずき

- 上記の「保存に失敗しました」は、何度もコードを直して再デプロイしてもらったのに直らないという長い診断になった。`wrangler tail`の「Ok」表示は「Workerがクラッシュせず応答を返した」という意味でしかなく、400/404エラーでも「Ok」と出る、という誤解にも気づかず遠回りした
- 宿泊先・総費用タップの新機能を実装した直後、ユーザーから「見れない・何も変わらない」という報告があったが、確認するとブラウザではなく**TestFlight（stale化した過去のネイティブビルド）**で確認していたためだった。フロントの変更はGitHub Pagesには即反映されるが、TestFlightは手動でビルドし直さないと反映されない、という2つの配信経路の違いに気づいた
- 既存のPlaywright回帰スイート（`test/ui.smoke.js`）が、DAY28で「÷人数」電卓を廃止し割り勘（立て替え）機能に置き換えたときに追随できておらず、存在しない`.cost-split-toggle`要素を探して壊れたままになっていた

## 解決方法

- デプロイ関連：`git pull`→`wrangler deploy`の順序をユーザー自身に徹底してもらい、`CONTEXT.md`に「`wrangler deploy`の前に必ず`git pull`」として明文化した
- TestFlight関連：以後、「保存できない」等の報告を受けたら、まず「TestFlightで見ていますか？それともブラウザですか？」と確認する運用に変えた
- 壊れていた`test/ui.smoke.js`：割り勘（立て替え）機能の実際のUI（`.cost-payer-toggle`→払った人／割る人のチップ選択→「参加者全員で均等割り」）に合わせてテストを書き直し、通るようにした

## 今日できるようになったこと

- 動画のサムネイルが写真と同じグリッドで表示される
- 宿泊先が、宿泊日ごとの実際の予定に基づいて「何泊目にどこ」と表示される
- 総費用をタップすると、参加者ごとの内訳金額が見られる

## 今日の動画で使えるポイント

1. 「保存に失敗しました」という一見コードのバグらしい報告が、実は開発者側の運用ミス（デプロイ前のgit pull忘れ）だった、という誰にでも起こりうる罠。`wrangler tail`の「Ok」表示が実は失敗ステータスも含む、というツールの誤解も一緒に学べる
2. GitHub Pages（Web版、push即反映）とTestFlight（ネイティブアプリ版、手動ビルドが必要）という2つの配信経路の違いを理解していないと、「直したのに直っていない」という混乱が起きる
3. 機能を1つ廃止して別の機能に置き換えたとき、実装のコードだけでなく回帰テストも一緒に更新しないと、テストスイートがサイレントに壊れたまま放置されてしまう（セルフレビューの運用があっても、テストコード自体の追随漏れは別途気づく必要がある）
