## 置き場所の決めごと

**いま2つの方式が混ざっています。** 方針を決め直す必要があります。

| 方式 | 対象 | 経緯 |
|---|---|---|
| 1リポジトリの中でフォルダ分け | DAY3〜6（`my-app/apps/dayNN-アプリ名/`） | DAY6 で整理。新規リポジトリを作る権限が無かったため（`403 Resource not accessible by integration`） |
| アプリごとに別リポジトリ | DAY7（`day07-soccer-attendance`） | 同じ403は出たが、**本人が GitHub の画面で作成**して解決した |

```
my-app/
  index.html            全アプリへのトップページ
  apps/dayNN-アプリ名/  各日のアプリ（1アプリ1フォルダ）
  docs/                 企画のルール・ロードマップ・日次ログ
  .claude/              開発時間を自動記録するフック
```

403 は「AIが作れない」だけで、**人が画面から作れば別リポジトリにできる**ことが DAY7 で分かりました。
どちらに寄せるかは未決です。決めるまでは現状のまま（DAY3〜6 は `apps/`、DAY7 は別リポジトリ）とし、
**記録はどちらの場合も `docs/logs/dayNN.md` に集約**します。アプリのフォルダやリポジトリには置きません。

別リポジトリにする場合は `templates/app-repo/` の中身（`CLAUDE.md` と、時間を記録する `.claude/`）を
そのリポジトリの直下にコピーします。

DAY1（くじ引き）と DAY2（ミリオネア）はまだ入っていません。手元にコードがあれば追加してください。

## 時間の計測について

`.claude/` のフックが、セッション開始・送信・応答完了の時刻を `.claude/time/` に記録します。集計は
`node .claude/hooks/timelog.js report`。

**ただし DAY7 で、リモート環境（ブラウザ版 Claude Code）では効かないことが分かりました。** アプリの
リポジトリを作業ディレクトリにしてセッションを開始しないとフックが発火せず、さらに待ち時間中はコンテナの
時計が進まないため経過時間も取りこぼします。**開始・終了時刻は人間が控えてください。**

AI稼働は「送信してから応答し終えるまで」の合計で、入力・検討している時間は入りません。ただし内部の
計算時間は取得できないため、応答時間の合計＝近似値です。ログにもそう書きます。
