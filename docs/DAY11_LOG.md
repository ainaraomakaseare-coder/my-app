# TikTok / Reels 用の材料

**一番驚いたこと**
「Vercelは4.5MBまでしか受け取れない」——動画投稿アプリなのに、動画を通せないサーバーだった。ブラウザからストレージへ直接送る方式に設計変更した。

1. 「動画投稿アプリ作ってたのに、サーバーが動画を通さなかった」

```
毎分  Supabase Cron（時計係）
  ↓ HTTPで叩く
Vercel の /api/worker（作業係）
  ↓
「時間が来た投稿ある？」とDBに聞く
  ↓
あれば1手だけ進めて、途中経過をDBに書く
```

**時計係と作業係を分けたのが肝。** Vercelの無料タイマーは1日1回しか鳴らないので、毎分の見張りだけSupabaseに任せた。

## 発生した費用

**0円。** Xのチャージ（$5）を見送ったため。しかも調べた結果、**A8.netの掲載対象にXは含まれていない**ので、アフィリ目的なら今後も不要。

## 再現するための手順

1. Supabaseでプロジェクトを作り、SQLを流し、非公開バケットを作る
2. `pg_cron` と `pg_net` を有効化
3. Vercelにデプロイし、環境変数を入れて**再デプロイ**
4. Supabase Cronから毎分 `/api/worker` を叩く
5. 各SNSの開発者登録 → コールバックURL登録 → 鍵を環境変数へ

## 有料noteにすると価値がありそうなポイント

- **二重投稿を防ぐSQL 1文の解説**（取得と記録を同じ文で行う理由）
- **4つのSNS APIの「渡し方」の違い一覧**（調べ直すと数時間かかる）
- **無料枠の見えない制限まとめ**（Vercel 4.5MB / Cron 1日1回 など、踏むまで分からない）
- **エラーの切り分けを自分で書く**という発想（401に文字数を出したら5分で解決した実例）
