## 発生したエラー・つまずき

### 事前調査で潰したもの（実装前に判明）

| # | 内容 |
|---|---|
| 1 | **Vercel Cron は無料プランだと1日1回・UTCのみ・指定時刻から1時間以内のどこか**。予約投稿には使えない → 時計係を Supabase Cron に分離 |
| 2 | **Vercel は1リクエスト 4.5MB まで**。動画をサーバー経由で送ると Shorts 一本すら通らない → ブラウザから Supabase へ直接送る方式に変更 |
| 3 | **X は `media.write` が別途必要**。よく紹介される4つの権限だけだとテキストは通るのに動画で403 |
| 4 | **YouTube は監査を通るまで API 経由の動画が非公開に固定**される |
| 5 | **Google / TikTok / X はクエリ付きのリダイレクトURIを弾くことがある** → `?network=x` から `/x` へ設計変更 |

### テストが見つけたもの

| # | 内容 |
|---|---|
| 6 | **再試行のときだけ、履歴から「次の一手」が抜けていた**。3回失敗するまで、何を直せばいいか分からない状態だった |

### 実際に踏んだもの

| # | 内容 | 解決 |
|---|---|---|
| 7 | **Production Branch が `main` のまま**で、デプロイされていたのはチンチロだった（`404 NOT_FOUND`） | Settings → Environments → Production の Branch Tracking を変更 |
| 8 | **日本語をHTTPヘッダーに入れると永久に一致しない**。`＃Anonパスワード` を Cron の鍵にしていた | 半角英数字のみに変更 |
| 9 | **`SUPABASE_URL` の貼り間違い**（`/rest/v1` 付きを貼ると `PGRST125`） | アプリ側で origin だけを取り出すよう修正。どの貼り方でも動く |
| 10 | **鍵が31文字 vs 13文字**。Vercel だけ更新して Cron 側が古いままだった | 401時に文字数と文字種を返すようにして特定 |
| 11 | **`pg_cron` / `pg_net` が未導入**（`relation "cron.job" does not exist`） | `create extension` を実行 |
| 12 | **Supabase Cron の Timeout 上限は 5000ms**（55000 を指定して弾かれた） | pg_net は非同期なので5秒で問題ないと判明 |
| 13 | **DAY8のInstagramトークンが失効**（エラーコード190） | Meta で再発行 |
| 14 | **`instagram_content_publish` と `instagram_business_content_publish` の紛らわしさ**。`business` の有無で経路が違う | 不要な審査申請を回避 |
| 15 | **アップロード中に予約ボタンが押せてしまう**。20MBの動画の保存中に押すと「画像か動画が必要です」と出て、直後に✅が出るので成功と失敗が同時に並ぶ | アップロード中はボタンを止め、開始時に古いエラーを消す |
| 16 | **TikTokだけ、利用規約とプライバシーポリシーのURLが登録必須**。他の3SNSでは求められない | アプリ内に2ページ作成 |
| 17 | **TikTokはURLの所有権証明を要求**。`vercel.app` は自分のドメインではないのでDNS方式が使えない | URL prefix 方式（署名ファイル）で通過 |
| 18 | **TikTokの Production フォームを埋めていた**。デモ動画の提出を求められ、審査ルートに入りかけた | Sandbox タブに切り替え |
| 19 | **TikTokサンドボックスでは `video.publish`（直接投稿）が提供されない**。使えるのは `video.upload`（下書き送信）だけ | 下書き方式にコードを書き換え |
| 20 | **TikTok は本番とサンドボックスで鍵が別**。`client_key` エラーで停止 | **未解決。ここで時間切れ** |
| 21 | **コマンドプロンプトと PowerShell でコマンドが違う**（`Get-ChildItem` が動かない） | `dir /s /b` に読み替え |
| 22 | **開発環境から Meta / X / Supabase に通信できない**（DAY8と同じ） | 実通信の確認は ainaraさんの画面で行う分担に |

## 今日できるようになったこと

- **自分のPCを閉じていても、クラウドが指定時刻に処理を実行する仕組みを作れるようになった**
- クラウドDB（Postgres）とストレージを使えるようになった
- 定期実行（Cron）を設定できるようになった
- 同じ内容を複数SNSへ出し分ける設計ができるようになった
- **二重送信を防ぐ考え方**（取得と記録を1文で行う）を実装できるようになった
- 失敗を媒体ごとに閉じ込め、部分再実行できる設計ができるようになった
- OAuth のリフレッシュトークンを扱えるようになった（DAY8はトークン直貼りのみ）
- タイムゾーンを設計で殺す方法を身につけた（保存はUTC・表示のみJST）
- 秘密情報をクラウドの環境変数で管理できるようになった
- **利用規約・プライバシーポリシーを用意する必要があること**を知った
