# 日ごとの天気を「場所を入力→自動取得」から「アイコンを選ぶだけ」に変える

日ごとの天気は、これまで「場所（市区町村名など）を自由入力→Open-Meteoでジオコーディング→天気取得」という流れだった。しかしどの粒度で地名を入れればいいか本人に伝わらず、大阪旅行で「ユニバーサル」と入れたらアメリカ・オーランドのユニバーサル・スタジオの天気になる、という事故が起きた（近くの日から候補を絞る対策を入れたあとも、そもそも「地名を入れる」という操作自体が分かりづらい）。天気・気温の自動取得は「その日の記録の雰囲気を添える」程度の位置づけで、精度も求められていない。**それなら地名を当てさせる入力欄ごと無くし、天気を本人がアイコンで直接選ぶ方式にする**と決めた（2026-09-26）。

**決めたこと**：
- UIから「場所」の入力欄・プロンプト（`promptDayPlace`）を無くした。日の見出し横のボタンは、天気アイコン＋ラベル（☀️晴れ／🌤️晴れ時々くもり／☁️くもり／🌧️雨／⛈️雷雨／❄️雪）を選ぶ・選び直すためだけのボタンになった（未選択なら「天気を選ぶ」）。気温は持たない。
- 場所（`place`・`lat`/`lon`・`admin1`・`country`）自体は無くしていない。時差判定・マイログの「訪れた都道府県・国」のために今も必要なので、その日の最初の「記録の地図」の位置から自動で入れる仕組み（`autoSetDayPlace`、DAY28〜の既存機能）に任せ、本人には見せない。
- 天気は既存の`day_infos.weather_code`・`weather_manual`列をそのまま使う（マイグレーション無し）。許可するコードを、既存の手動修正機能の10種から、アプリの6アイコンに対応する`[1, 2, 3, 61, 71, 95]`に絞った（`MANUAL_WEATHER_CODES`）。`weatherCode: null`を渡すと選択解除（「なし」）に戻せるようにした。
- 天気を選ぶために場所（`day_infos`行）が先にある必要はない。行が無ければ空の場所のまま作る。
- 表示に使わなくなったので、`autoSetDayPlace`・`refetchShiftedWeather`はもうOpen-Meteoへ天気を取りに行かない（Nominatimでの場所の逆ジオコーディングだけ行う）。`fetchDailyWeather`関数と旧`PUT /trips/:id/days/:date`（`setDayPlace`、地名を手入力する昔のエンドポイント）はコードとしては残したが、新しいUIからは呼ばない。

**避けたこと**：天気アイコンに温度入力を残すこと（「気温はどうせ自動取得の推定値に毛が生えた程度の精度」という前提と矛盾するため、いっそ無くした）。`day_infos`のデータを削除すること（古い自動取得・旧手動修正の値は消さず、表示側で6種のどれかに寄せて解釈するだけにした）。
