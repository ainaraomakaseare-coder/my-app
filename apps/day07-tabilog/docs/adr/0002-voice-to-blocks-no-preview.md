# 音声からの記録作成は、下書き確認を挟まず直接保存する

旅の足跡はこれまでAIを一切呼び出さないアプリだったが、「音声で話した内容を複数の予定・記録に自動分割する」機能の追加にあたり、初めてAI（OpenAI）呼び出しを導入する。ユーザーに「保存前に下書きを確認する画面を挟むか、直接保存するか」を確認したところ、直接保存（あとから普通の編集画面で直す）を希望された。AIの解釈がずれても、既存の編集・削除機能で十分にリカバリーできると判断したため、確認画面は作らない。あわせて、日付の判定もAIにはさせず、常に「今開いている日タブ」に固定する（話した順番で並べる）。評価などAIに推測させると事実と異なりやすい項目は、今回のスコープに含めない。

**追記（2026-09-14）**：時刻（Block.time）と費用の明細（Entry.costItems）は、当初「AIに推測させると事実と異なりやすい」としてスコープ外にしていたが、「話されたときは入れてほしい」という要望を受けて範囲を広げた。ただし判定基準は変えていない＝**話されていないことを推測で埋めない**のは変わらず、「明確に話された時刻・金額だけをそのまま拾う」形にとどめている（プロンプトで明示）。評価（★）は本人が押す行為に意味があるため、引き続きスコープ外のまま。

**追記（2026-09-30）：音声にも確認画面を挟むことにした（この決定を上書きする）**

オーナーの要望で、音声入力・メモ（AIで整理）を「スクショから予定を作る」（`docs/adr/0022`）と同じ形にした。**AIが候補を作ったあと、保存する前に確認画面（スクショと同じ画面）を出し、本人が直してから保存する**。上の「確認画面は作らない」を改めた理由は次の3つ。

- 時刻・費用・**場所（地図のピン）**まで候補に入れるようにしたため。場所は「浅草寺」を別の場所に取り違える、費用の桁を聞き違える、などが起きうる。直すなら保存前のほうが、保存後に記録を開いて直すより手数が少ない。
- スクショの確認画面（日付・時刻・見出し・種類・場所・費用を直す／要らない候補を外す）が既にあり、**同じ画面を使うので作る量が少ない**。画面が3つの取り込みで同じなので、覚えることも増えない。
- 別行動（自分だけの道。`docs/adr/0021`）に取り込むとき、日付・時刻が別行動の時間帯に収まっているかを保存前に見せられる。

変えていないこと：**話されていないことを推測で埋めない**（時刻・金額・場所は、話した／書いたものだけ。分からない項目は空欄のまま。プロンプトと、AIの出力の検証の両方で守る）。評価（★）はスコープ外のまま。音声の文字起こしは、これまでどおりその日の欄（DayInfoの`voiceTranscript`）に残す（確認して追加したときだけ。取り消したら何も残さない）。利用回数の枠の使い方も変えていない（音声は音声の枠、メモのAIはメモの枠。AIを呼んで候補ができた時点で1回消費し、確認画面で取り消しても戻らない）。

仕組みは`docs/adr/0022`の「2026-09-30追記」を参照（`POST /trips/:id/voice-scan`・`text-scan`が候補を返し、`POST /trips/:id/import-blocks`が保存する）。旧エンドポイント（`voice-entries`・`text-entries`・`memo-blocks`）は、古いアプリのために残してあるが、今のアプリは使わない。
