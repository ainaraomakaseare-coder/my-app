# マイログの「訪れた都道府県・国」を外す操作を、アカウント全体からTripごとに変える

TestFlight（90）でオーナーから報告：マイログで「アメリカ」の「マイログから外す」を押した（ブラジル・アルゼンチン旅行のつもりだった）ら、別の旅行（ワールドカップ・大谷観戦旅）のアメリカも一緒に消えた。原因は`mylog_place_overrides`（v23）が`account_id + kind + name`だけをキーに持つ、**Tripをまたいだアカウント全体のhide/show**だったこと。しかも一度外すと元に戻す導線が無かった。オーナーの新しい設計（旅行ごとに外す・戻す、総計は「出てくる旅行すべてで外されている」ときだけ落ちる）をそのまま実装した（2026-09-28）。

**決めたこと**：
- `mylog_trip_place_overrides`（`account_id, trip_id, kind, name, created_at`、複合PK）を新設。**外すことしかできない**（行があれば「外した」、無ければ「外していない」。v23の`mode`＝hide/showのような区別は無くした＝乗り継ぎ判定を逆に強制カウントする「行った場所として数える」機能はこの表からは落とした）。
- `visited-places.js`の`aggregateVisitedPlaces`は`overrides`ではなく`tripOverrides: [{tripId, kind, name}]`を受け取る。ある場所が総計（`prefectures`/`countries`）から落ちるのは「**出てくる旅行すべてで**、その旅行の`tripOverrides`に含まれている」ときだけ。片方の旅行だけ外しても、もう片方で数えていれば総計には残る。旅行ごとの一覧`tripPlaces`（乗り継ぎだけの場所は含めない、外した場所も`excluded:true`で残す＝消えない）を新しく返す。
- 新しいエンドポイント`POST /mylog/trip-places`（`{email, tripId, kind, name, mode: 'exclude'|'include'}`）。認証・所有者確認は既存の`/mylog/places`と同じ`resolveEmail`＋`accounts`テーブル。加えて`trip_members`で「そのアカウントが指定tripIdに参加しているか」も確認する（他人の旅行を外せないように）。
- **v23の`mylog_place_overrides`テーブル・`POST /mylog/places`エンドポイントは削除しない**（古いアプリがまだ呼ぶ可能性があるため、呼び出し自体はこれまでどおり成功させる＝エラーにしない）。ただし`getVisitedPlaces`はこのテーブルをもう読まない。つまり**旧版で「外した」場所（アメリカなど）は、今回の変更で再びマイログの総計に出るようになる**（不具合の直接の直し方であり、意図した挙動）。
- UI：マイログ画面に「旅行ごとの訪れた場所」セクションを新設（`renderMyLogTripPlaces`）。旅行ごとにチップを並べ、チップ内の「外す」を押すとその場で`is-excluded`（灰色）＋「戻す」に変わる（消えない＝いつでも戻せる、選択→別画面の詳細パネルを経由しない）。既存の「訪れた都道府県・国」（総計）は読み取り専用にし、そこにあった「マイログから外す」ボタンは削除した。

**避けたこと**：`mylog_place_overrides`テーブル自体を消すこと（古いクライアント互換のため残す。docs/CLAUDE.mdの「初心者向けに分かりやすく」の観点でも、動いているものを急に壊さない）。「乗り継ぎと判定された国を逆に数える」（v23のmode='show'）機能を新しい表に引き継ぐこと（今回のオーナー要望はあくまで「外す・戻す」の旅行単位化で、乗り継ぎ判定そのものの手動修正は範囲外と判断した。要望があれば別途）。
