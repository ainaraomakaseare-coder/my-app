# 費用の明細に外貨を入れられるようにする（円換算はレートを自動取得しつつ本人が直せる）

海外旅行の記録では、費用の明細（`entry.costItems`）を現地通貨のまま入れたい（クレジットカードの明細と
突き合わせやすい・レシートの金額をそのまま入れられる）が、割り勘の精算（`tripBalances`/`settlementPlan`）
は誰がいくら貸し借りしているかを1つの単位で比べる必要があるため、**円に揃える必要がある**。為替レートは
日々変わり、かつ実際にカードで決済されたレートは公表の基準レートと数%ずれることがあるため、「自動取得
だけ」でも「手入力だけ」でも困る。**自動取得しつつ本人が直せる**方式にする（2026-09-27）。

**決めたこと**：
- costItemに`currency`（ISO 4217、例："USD"）・`rate`（1`currency`あたりの円）を追加できる（どちらも
  任意項目）。`amount`は常にその通貨での金額（円の費用行はこれまでどおり整数円、外貨は小数第2位まで）。
  `currency`が無い・`'JPY'`のcostItemは、これまでどおり「amountがそのまま円」という意味のまま変わらない
  （旧バージョンのアプリが送ってくるcostItemsとの後方互換。DBのマイグレーションも無い＝`cost_items`列は
  元々JSON文字列なので、新しいフィールドを持つcostItemもそのまま保存できる）。
- 円換算は`Core.costItemJpy(item)`という1つの純粋関数に集約する：`currency`省略／`'JPY'`ならamountが
  そのまま円、それ以外は`Math.round(amount * rate)`。**合計・貸し借りを扱う関数（`entryCostTotal`/
  `blockCostTotal`/`tripTotalCost`/`tripBalances`/`costBreakdownByPerson`）はすべてこれを経由する**よう
  書き換えた。表示用の`Core.formatCostItemAmount(item)`も、円は`formatYen`と同じ、外貨は元の金額と
  円換算を両方見せる（例：「US$25.00（¥3,737）」。精算画面の内訳と一致しているか本人に分かるように）。
- レートは、その費用行があるBlockの日付でWorkerの`GET /rates?date=YYYY-MM-DD&currency=XXX`から自動
  取得する。取得元は2段構え：
  1. Frankfurter（ECB基準レート、無料・APIキー不要、約30通貨・過去日対応）
  2. 対応していない通貨（ARSなど）はfawazahmed0/currency-api（jsDelivr配信）にフォールバック
     （日付ごとのバージョン→無ければ`@latest`の順。`@latest`を使ったときはUIに警告を出す）
  結果は`caches.default`にキャッシュする（詳しくは`worker/README.md`の該当節・`worker/src/rates.js`）。
- **一度取得・入力したレートは、通貨を変えない限り取り直さない**（本人がカード明細に合わせて直した値を
  尊重する。フォームを開き直すたびに変わってしまうと、直した意味が無くなるため）。
- 円以外を選ぶと、金額欄はカード明細通りの小数（例：25.50ドル）を受け付けるよう`step`を`0.01`に変える。
  サーバー側のバリデーション（`validCostItems`）も、`currency`がある行だけ小数第2位までを許可し、`rate`
  は`0 < rate < 1,000,000`を必須にする。
- 旅行ごとに「最後に選んだ通貨」を`localStorage`（`tabilog:last-currency:<tripId>`）に覚え、次の明細行・
  レシート読み取り結果の初期値にする（同じ旅行では同じ通貨の支払いが続くことが多いため。トリップを
  またいだ使い回しはしない）。

**避けたこと**：
- レート取得を単一の情報源に頼ること（Frankfurterは約30通貨までしか対応しておらず、アルゼンチンペソ
  （ARS）のように対応していない通貨があるため、フォールバックを用意した）。
- 費用行の金額を「常に円に変換してから保存する」方式（本人が入れた元の金額・レシートの金額と表示が
  食い違ってしまい、あとで見返したときに「本当はいくら払ったか」が分からなくなる）。amountは常に
  入力した通貨のままの金額を保持し、円換算は表示・集計のたびに計算する。
- 一度取得したレートを毎回自動で上書きすること（本人がカード明細の実際のレートに直した値が、フォームを
  開き直すたびに公表レートへ戻ってしまうと、直した意味が無くなる）。通貨を変えたときだけ取り直す。
