# 写真から旅程を作る

オーナーから「iPhoneの写真を10枚くらい選んだら、撮影場所と時刻を読み取って行程を作ってほしい」という要望（2026-10-22）。0025（写真の撮影場所を記録の地図に入れる）の読み取りを使い、旅行の詳細の下にある取り込みのボタンに「写真から旅程を作る」を足した。

**決めたこと**：
- **写真は最大30枚**。iPhoneアプリは`@capacitor/camera`の`pickImages`で写真ライブラリから選び、`exif.GPS`（場所）と`exif.DateTimeOriginal`（撮影日時。プラグインは`{Exif}`の中身を`exif`として返す）を読む。ブラウザはJPEGのExifから直接読む（`Core.jpegExifFromBuffer`）。
- **まとめ方（`Core.photosToStops`）**：撮影時刻の順に並べ、その場所の最初の写真から**0.5km以上**離れた、または前の写真から**2時間以上**空いたら次の立ち寄り先。場所の無い写真は時間が続いていれば今の立ち寄り先へ、時刻の無い写真は0.5km以内のいちばん近い立ち寄り先へ。時刻も場所も無い写真は使わない（確認画面で枚数を伝える）。
- 撮影日時はExifの値（撮影した土地の時刻）をそのまま予定の日付・時刻にする（時差は直さない。アプリの予定も現地時刻のため）。
- **場所の名前**：新しい`GET /places/nearby?lat=&lng=&lang=`で、撮影場所から半径150mの中でいちばん知られている場所（Places API (New) Nearby Search、`rankPreference: POPULARITY`、`displayName,types`だけ）。キーが無い・失敗したらNominatimの逆ジオコーディング（施設名、無ければ地区名）。1回の取り込みで調べるのは**12か所まで**、1か所ずつ順に。`WRITE_RATE_LIMITER`で1分30回まで。名前が分からなければ見出しは「写真の場所」。
  - 費用：Nearby Search Proは**月5,000回まで無料**、超えると1,000回あたり$32（1か所約5円）。
- 予定の地図は**写真の撮影場所の座標**（施設の座標ではない。実際にいた場所を残す）。種類はGoogleの`types`から食事／宿泊／観光（`Core.categoryForPlaceTypes`）。
- 候補は**スクショ・メモと同じ確認画面**（各候補に写真の小さい一覧）で直して、`/import-blocks`で保存（Workerの保存処理は変えていない）。保存のあと、各予定の記録に写真を付ける（記録が無ければ作る。`writeData`なので電波が無ければ送信待ちに積む。1つの記録に20枚まで）。
- **AIは使わない**。AIの回数も減らない。

**避けたこと**：AIで場所の名前や文章を作ること（回数・費用がかかり、名前は場所検索のほうが正確）。施設の候補を複数出して選ばせること（必要になれば`/places/nearby`が候補を返すようにする）。

**Workerの変更あり**（`/places/nearby`）。デプロイ前の古いWorkerでも、名前が「写真の場所」になるだけで動く。iPhoneで場所を読むには`@capacitor/camera`入りのビルド（1.4.1以降）が要る。
