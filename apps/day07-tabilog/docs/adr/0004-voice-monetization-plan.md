# 音声入力（AI機能）を有料化する方針

音声入力はこのアプリで唯一AIを呼び出す機能で、使うたびにOpenAIへの実費が発生する。無料のまま公開範囲が広がると、利用が増えるほど赤字が拡大するリスクがあるため、有料化の方針を`interview-me`で確認した。

**決めたこと**：
- 無料プランでは音声入力機能そのものを使えなくする（他の機能は今まで通りすべて無料）
- 支払うのは旅行を作った人（幹事）で、参加者ではない
- 価格は月額のサブスクリプション制。ベーシック（月300円・月10回まで）／プレミア＋（月1000円・月50回まで）の2段階
- サブスクに入らなくても、回数券（買い切り500円・10回分）で単発利用できる
- どのプランでも**1回の録音は3分まで**というアプリ側の制約を必ず伴わせる。これにより「1回あたりの実費」の上限が決まり、上限回数を全部使い切っても赤字にならない価格設定ができる（時間の上限を外すと、長時間の録音で実費が予測できなくなるため、プレミア＋でも時間の上限だけは変えない）
- 決済はStripeを使う（サブスクリプション管理・買い切り決済の両方に対応させる）

**見送ったこと**：
- 参加者ごとに個別課金する方式（今のゲスト参加者＝ログイン不要という設計と相性が悪いため）
- 音声以外の機能（写真・旅程作成など）の有料化（今回のスコープ外）
- 本番運用に向けた税務・インボイス対応（Stripe本番切り替え時に別途検討）

**未着手**：Stripeのアカウント登録・テストモードでのサブスク実装・回数制限のサーバー側実装。まず外部サービスに依存しない「1回3分で自動的に録音を止める」機能だけ先行して実装した（`docs/adr`本文と`CONTEXT.md`の「音声からの記録作成」参照）。

## 後日の変更（DAY26〜）

- 無料プランでも月2回までは音声入力を使えるようにした（「無料プランでは使えない」から変更。有料プランへの入り口として月2回だけ体験できる形にした方が良いと判断）
- 新規登録時の回数券3回分ボーナスは維持する（機能の良さを知ってもらうための特典なので残したい、という判断）。ただし、アプリ内に自己サービスのアカウント削除機能（Appleのガイドライン5.1.1(v)対応）を追加したことで、「削除→同じメールで再登録」を繰り返すだけで特典を無限に得られる抜け道が一時的に生じたため、以下の対策をセットにした
- アカウント削除は`accounts`の行をDELETEせず、名前・プラン・回数券などの個人情報だけを空にするUPDATEにする。emailの行自体は残すことで、再登録時に`getOrCreateAccount()`が「既存アカウント」と判定し、新規登録特典の再付与を防ぐ
- 同じ理由で、アカウント削除時に無料プランの月間上限（`voice_uses_this_period`）もリセットしない（削除→再登録を繰り返すだけで無料プランの月2回を何度でも復活させられてしまうため）。月が変わったときの通常のリセットは`resetPeriodIfNeeded()`が別途行う

## メモの取り込み（2026-09-26〜）

「メモから記録する」を無料でも使いやすくした。
- **決まった形のメモはAIを使わない**：「10時 新宿」のように時刻で始まる行＝予定、その下の行＝記録、「2日目」「4/2」の行＝日付の切り替え。アプリ側（Core.parseMemo）で分けて `POST /trips/:id/memo-blocks` で保存する。AIの費用がかからないので、ログインも回数も要らない（何回でも無料）
- **形が崩れたメモはAIで整理**し、音声とは別の「メモの枠」を使う（accounts.memo_uses_this_period）。月の回数は 無料10・ベーシック30・プレミア＋100（MEMO_MONTHLY_LIMIT）。有料プランは、以前（音声と共通の枠で10・50）より減らないようにした。枠を使い切ったら回数券を使う
- 音声・AIで整理のときだけ、ログイン・AIへの送信の同意・回数を確かめる（以前は画面を開く時点で求めていたので、回数が無いとメモも使えなかった）
