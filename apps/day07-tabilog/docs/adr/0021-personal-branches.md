# 自分だけの道（別行動の分岐）：時間帯ごとに、自分の予定でみんなの予定を置き換える

これまでの「別行動」は、同じ予定（Block）の下に記録（Entry）を複数ぶら下げるだけで、**地図でふりかえる・動画でシェアの道のりは全員で1本**だった。オーナーの要望：「14時から17時は自分だけ別のところ（美術館→カフェ）に行った」を、自分の予定として書き、その人の道のりで地図・動画を作れるようにしたい。

**決めたこと（オーナー）**：

- ログインしているアカウント参加者は、ある日の時間帯（例 14:00〜17:00）に**分岐**を作り、その中に自分の予定（記録・地図つき、ふつうの予定と同じ）を書ける。
- **全員が見られるが、直せるのは持ち主だけ**（サーバーが確かめる）。
- **切り替えて見る**：旅行の画面の上に「表示する道：みんな／○○」。「みんな」では、分岐の開始時刻の位置に小さなカード（「アリス：14:00〜17:00 別行動（美術館→カフェ）」）が出て、押すとその人の道に切り替わる。人の道では、その人の分岐の時間帯にある「みんなの予定」のかわりに、その人の分岐の予定が並ぶ。時間帯の外はみんなの予定のまま。
- **地図でふりかえる・動画でシェアは、選んでいる人の道で作る**（既定は「みんな」＝今までと同じ）。時差は分岐の予定にも同じ規則（地図のピンで決め、無ければ直前を引き継ぐ）。
- **将来は有料機能、いまは無料**：入口の判定を`canUseBranches(account)`の1か所に集め、いまは常にtrue。課金を始めたらここだけ変える。
- ログインしていない人は、分岐を見られるが作れない（「ログインすると自分の別行動を追加できます」と案内）。

**設計**：

- **DB**：`branches`（id・trip_id・account_id・date・start_time・end_time・title・created_at・updated_at）を新設し、`blocks.branch_id`（空文字＝みんなの予定）を足す（`migrations/0030_branches.sql`）。分岐は「日をまたがない1日の中の時間帯」（始まり＜終わり）。同じ人の分岐どうしは時間帯が重ならない（隣り合うのは可。別の人とは重なってよい）。日付は作ったあとで変えられない（変えたいときは作り直す。分岐の中の予定の日付が分岐に固定されているため）。
- **API**（`worker/src/index.js`。入力チェックと権限の判定は純粋関数`worker/src/branches.js`）：
  - `POST /trips/:id/branches`（本文 `{date, startTime, endTime, title?}`。ログイン必須・その旅行のアカウント参加者だけ）
  - `PATCH /branches/:id`（時間帯・タイトル。持ち主だけ）／`DELETE /branches/:id`（持ち主だけ。中の予定・記録・評価・いいね・コメントも1つのbatchで消す）
  - `POST /trips/:id/blocks`に`branchId`を付けると分岐の中の予定になる（持ち主だけ。日付は分岐の日に固定）。`PATCH/DELETE /blocks/:id`、記録の作成・更新・削除・移動（`/blocks/:id/entries`・`/entries/:id`・`/entries/:id/move`）は、分岐の中の予定なら持ち主だけ（他の人は403、ログインなしは401）。**みんなの予定の書き込みは今までどおり（トークン不要）**。分岐をまたぐ記録の移動は400（`different_branch`）。
  - `GET /trips/:id`が`branches`（持ち主のaccountIdと名前つき。メールは含めない）を返し、予定に`branchId`が付く。
  - 旅行の削除・アカウントの削除で、分岐と中身も消える。日程をずらす（`shiftDays`）ときは分岐の日付もずらす。旅行から「抜ける」だけでは分岐は消さない（自分が書いた記録を消さない、既存の方針と同じ）。
- **マイグレーション前にデプロイしても壊れない**：`GET /trips/:id`は`branches`テーブルが無ければ`branches: []`を返し（try/catch）、`blocks.branch_id`が無ければ全部「みんなの予定」として扱う。分岐を作ろうとしたときだけ503（`branches_not_ready`）。並べ替えの対象は`branch_id = ''`の予定だけ（列が無ければ全部）。サブリクエストは1リクエストにつき一定数のD1クエリ（分岐の削除は1つのbatch）。
- **画面側の持ち方**：旅行を開くと、予定を`state.blocks`（みんなの予定）と`state.branchBlocks`（分岐の中の予定）に分ける。時差・宿泊・並べ替えなど「みんなの予定」を前提にした既存の機能は`state.blocks`だけを見るので変えていない。**費用（総費用・精算・内訳）・アルバム・記録の検索は両方を見る**（分岐の中の費用も、ふつうの記録と同じく精算に入る。払った人・割る人はその明細で決まる）。
- **見せる並びは純粋関数（Core、`test/data.test.js`でテスト）**：`visibleBlocksForView`（人の道での旅行全体の予定。地図でふりかえる・動画・時差の計算が使う）、`dayTimelineItems`（その日のタイムライン。予定・カード・帯）、`blocksInBranchWindow`（時間帯に入るみんなの予定。開始ちょうどは含み終了ちょうどは含まない。時刻なしの予定は入れない）、`branchViewOptions`・`resolveViewAccountId`・`branchCardText`・`validateBranch`。カードと帯は「開始時刻以降で最初の時刻あり予定」の手前に入れ、自分の分岐の時刻なしの予定は帯の直後に並べる。
- **切り替えの記憶**：選んだ人は旅行ごとに端末（localStorage、`tabilog:branch-view:<tripId>`）に覚える。その人の分岐が無くなったら「みんな」に戻す。
- **人の道を見ているあいだ**は、みんなの予定の並べ替え（長押しドラッグ）を出さない（みんなの並びを変える操作なので「みんな」で行う）。別行動の中の予定は、記録の別の予定への移動も出さない。
- **時差**：分岐の中の予定の地図・到着地も`loadTripZones`で調べ、人の道を見るときはその道の並び（`activeBlocks()`）で時差を計算し直してから、ふりかえり・動画に渡す。

**画面**：旅行の上に切り替え（別行動がある旅行だけ）。タイムラインの「予定を追加」の下に「ここから別行動」（ログインなし・未参加には案内の文だけ）→シートで時間帯（始まり・終わり）とタイトル（任意）を入れる。作ったあとは自分の道に切り替わり、帯の「予定を追加」で予定フォームを開く（日付は固定、時刻は別行動の時間帯の中）。持ち主以外には、別行動の中の予定は見るだけ（編集・記録追加のボタンを出さない）。

**見送ったこと・割り切り**：

- 分岐の中の予定への音声・メモでのまとめ記録（作られるのは「みんなの予定」）。
- 他の人の分岐の記録に、★評価をつけること（評価は記録フォームから行うため、持ち主以外はフォームを開けない。必要になったら評価だけの入口を足す）。
- 時刻なしの「みんなの予定」は、別行動の間も消さずに残る（いつ起きたか分からないため）。
- 分岐の日付の変更、日をまたぐ分岐（深夜0時をまたぐ別行動は2つに分けて作る）。
- 分岐の中の予定の並べ替え（時刻順・時刻なしは作成順の自動並びのみ）。
- 旅行から抜けた人の分岐は残る（読めるが、参加し直すまで新しく作れない。すでにある分岐の予定は、セッションが有効なら持ち主なら直せる）。

**確かめたこと**：`node test/data.test.js`・`node worker/test/branches.test.mjs`・`node worker/test/branches-api.test.mjs`（`node:sqlite`の本物のSQLite上で、権限・重なり・削除の連鎖・マイグレーション前の挙動を通しで確認）。画面は、モックのAPIに差し替えたローカルのページ（本番のAPIは呼ばない）で、切り替え・カード・帯・シート・予定フォーム・ログインなし／未参加の表示を確認した。**確かめていない**：本番のD1・実機（iOS）、地図でふりかえる・動画の画面そのもの（渡す予定の選び方までをテストで確認）。

## 2026-09-30 追記：日をまたぐ別行動（複数日の分岐）

オーナーの要望：「一人が夜通しどこかへ行く」2日にわたる別行動も、自分の道として書きたい。**分岐は開始（日付＋時刻）から終了（日付＋時刻）まで、複数日にまたがってよい**（例 6/27 14:00〜6/28 12:00）。上の「割り切り」にあった「日をまたぐ分岐は不可（2つに分ける）」は、この節で置き換わる。

**DB**：`branches.end_date TEXT NOT NULL DEFAULT ''`（空＝`date`と同じ＝1日）。オーナーが0030を本番でまだ実行していなかったため、`0030_branches.sql`のCREATE TABLE自体に`end_date`を入れた。すでに古い0030を実行したDB向けに`0032_branch_end_date.sql`（`ALTER TABLE branches ADD COLUMN end_date ...`。新しいCREATEで作った場合は「duplicate column name」エラーになるだけで害はない）を用意した（0031は`video_exclude`で使用済み）。

**Worker**（`worker/src/branches.js`の純粋関数＋`index.js`）：
- `validateBranchInput(input, others, excludeId, {tripStart, tripEnd})`：終わり（終わりの日＋時刻）が始まりより後／始まり・終わりの日が旅行の日程の中（旅行に日程があるときだけ）／同じ人の別の分岐と、**日をまたいだ絶対時刻で**重ならない（ぴったり隣り合うのは可）。共有予定のルールは変えない。
- `validateBranchBlockPlacement(branch, date, time)`：分岐の中の予定の日付は始まり〜終わりの日の中、時刻は「始まりの日は開始以降、途中の日は1日中、終わりの日は終了まで（ちょうどは可）」。時刻なしは時刻を見ない。予定の作成（`branchId`つき。日付を省くと始まりの日）と更新（別の日への移動も分岐の日々の中だけ）で確かめ、外れると400（`date_out_of_branch`／`time_out_of_branch`）。従来は「分岐の日に固定」していたが、いまは分岐の日々から選ぶ。
- `PATCH /branches/:id`：終わりの日・時刻・タイトルを直せる（始まりの日は従来どおり変えられない。作り直す）。重なりの確認は、その人の同じ旅行の**全分岐**を見る（以前は同じ日だけ）。
- **`end_date`列が無いDBでも壊れない**：`rowToBranch`は`endDate = end_date || date`。1日の別行動はend_date列なしのINSERTで作れる。日をまたぐ別行動の作成・終わりの日の変更は、列を1回探って無ければ503（`branch_multiday_not_ready`）で断る。
- `shiftDays`：`date`に加えて`end_date`（空でないもの）もずらす（列が無ければ何もしない）。旅行・アカウントの削除は行ごと消すので`end_date`のための追加処理は無い。

**画面・Core**：
- `Core.branchWindowOn(branch, date)`が「その日の窓」（始まりの日は開始から、途中は0〜1440、終わりの日は終了まで）を返し、`blocksInBranchWindow`・`visibleBlocksForView`・`dayTimelineItems`が使う。`visibleBlocksForView`が地図でふりかえる・動画（`replayStops`／`buildVideoStory`）にもそのまま効く（時差の規則は変えていない）。
- タイムライン：人の道では、かかっている**各日**で、窓の中の「みんなの予定」がその人の分岐の予定に置き換わる（始まりの日は開始から、途中の日は1日中、終わりの日は終了まで）。「みんな」の表示では、始まりの日に従来どおりカード（「ひろや：6/27 14:00〜6/28 12:00 別行動（…）」）、**2日目以降はその日の先頭に小さなカード「ひろや：別行動中（〜6/28 12:00）」**（押すとその人の道に切り替わる。`dayTimelineItems`の要素に`continued: true`）。自分の道では2日目以降の先頭に帯が出る。
- 別行動シート：始まり（日付・時刻）と終わり（日付・時刻）。日付は旅行の日々から選ぶセレクト（終わりの日の選択肢は始まりの日以降。初期値は終わり＝始まりの日）。編集では始まりの日は固定。
- 分岐の中の予定フォーム：日付が、別行動の日々（始まり〜終わり）から選ぶセレクトになる。時刻は、その日の窓の中（`Core.validateBranchBlock`）。

**割り切り・注意**：分岐の終わりを短くしたときに、窓の外に出てしまう既存の予定は自動では消さない（その人の道の画面には出続ける。予定側を直すか削除する）。旅行から日程を短くして分岐が日程の外に出た場合も同様。

**確かめたこと**：Core・Workerの単体テスト、`node:sqlite`のAPIテスト（日またぎの作成・重なり・予定の日付／時刻の検証・日程外・shiftDays・削除の連鎖、end_date列が無い環境の挙動、0030／0032の実ファイルを別DBに流す確認）。**確かめていない**：本番D1・実機、画面（ブラウザ）での操作そのもの。

## 2026-09-30追記：スクショ・音声・メモの取り込みを別行動（自分だけの道）に入れる

取り込み3つ（スクショ・音声・メモ。仕組みは`docs/adr/0022`の同日の追記）を、別行動の中に入れられるようにした。

- **行き先の決め方**：自分の道を見ていて（`state.viewAccountId`＝自分）、選んでいる日が自分の別行動のどれかの日々の中なら、その別行動（日が重なる別行動が2つあれば、早く始まるほう。`Core.importTargetBranch`）。それ以外はこれまでどおり、みんなの予定に入れる。取り込みの入口（音声・メモの画面、スクショの画面）に「自分だけの道（美術館）に追加します（13:00〜18:00）」と出し、確認画面にも同じ帯を出す。**日タブの下の別行動の帯にある「予定を追加」は従来どおり1件ずつ作る入口**で、取り込みのボタンは日タブの下の既存の3つ。
- **日付・時刻**：AIの候補の日付は、別行動の日々の中に置く（1日だけの別行動＝その日に固定、日をまたぐ別行動の複数日モード＝別行動の日々からAIが選び、外れたら別行動の初日に置いて警告）。確認画面の日付は別行動の日々から選び、時刻は別行動の窓の中だけ（`Core.validateBranchBlock`。始まりの日は開始以降、終わりの日は終了まで、途中の日は1日中、時刻なしは見ない）。窓の外の候補は「別行動の…」の警告が付き、直すまで追加できない（時刻を直すと警告も数え直す）。
- **サーバー**：`voice-scan`・`text-scan`・`screenshot-scan`・`import-blocks`が`branchId`を受ける。分岐が無い／別の旅行なら404（`branch_not_found`）、**持ち主（セッション。`branchWriteGuard`）でなければ403（`forbidden`）でAIを呼ぶ前に断る**、`*-scan`の`date`が別行動の日々の外なら400（`date_out_of_branch`）。保存（`import-blocks`）は`validateBranchBlockPlacement`で日付・時刻を検証し直し、外れた項目は`errors`（`date_out_of_branch`／`time_out_of_branch`）で返して保存しない（ほかの項目は保存する。全部外れていれば400）。予定は`blocks.branch_id`付きで、記録と1回のD1バッチで作る。
- **文字起こし（DayInfo）は別行動では残さない**：その日の欄は「みんなの」情報で、別行動の中身が漏れるため。
- **画面の割り切り**：別行動の取り込みは、その日の別行動の日々のあいだだけ（日をまたぐ別行動では、複数日モードで別行動の日々に振り分ける）。「みんな」の表示で取り込むと、別行動の時間帯の中でも「みんなの予定」として保存される（既存のルールどおり）。自分のAIのJSONの取り込みも、同じ確認画面を通るので、別行動の中なら別行動に入る。
- **確かめたこと**：`worker/test/import-handler.test.mjs`（他人・ログインなしは拒否、存在しない・別の旅行の別行動は404、日の外は400、持ち主は候補を作れる、保存で`branch_id`が付く、時間帯の外・日をまたぐ別行動の始まる前／終わった後は保存しない、別行動の保存は文字起こしをDayInfoに残さない、fetchとD1の回数）、`test/data.test.js`、ブラウザでの確認画面（別行動の帯・日付の範囲・時間帯の外の警告と保存前のエラー・直して保存すると`branchId`が送られる）。**確かめていない**：本番D1・実機、日をまたぐ別行動での画面上の通し操作。
