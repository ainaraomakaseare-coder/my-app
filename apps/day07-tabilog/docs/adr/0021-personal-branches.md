# 自分だけの道（別行動の分岐）：時間帯ごとに、自分の予定でみんなの予定を置き換える

これまでの「別行動」は、同じ予定（Block）の下に記録（Entry）を複数ぶら下げるだけで、**地図でふりかえる・動画でシェアの道のりは全員で1本**だった。オーナーの要望：「14時から17時は自分だけ別のところ（美術館→カフェ）に行った」を、自分の予定として書き、その人の道のりで地図・動画を作れるようにしたい。

**決めたこと（オーナー）**：

- ログインしているアカウント参加者は、ある日の時間帯（例 14:00〜17:00）に**分岐**を作り、その中に自分の予定（記録・地図つき、ふつうの予定と同じ）を書ける。
- **全員が見られるが、直せるのは持ち主だけ**（サーバーが確かめる）。
- **切り替えて見る**：旅行の画面の上に「表示する道：みんな／○○」。「みんな」では、分岐の開始時刻の位置に小さなカード（「アリス：14:00〜17:00 別行動（美術館→カフェ）」）が出て、押すとその人の道に切り替わる。人の道では、その人の分岐の時間帯にある「みんなの予定」のかわりに、その人の分岐の予定が並ぶ。時間帯の外はみんなの予定のまま。
- **地図でふりかえる・動画でシェアは、選んでいる人の道で作る**（既定は「みんな」＝今までと同じ）。時差は分岐の予定にも同じ規則（地図のピンで決め、無ければ直前を引き継ぐ）。
- **将来は有料機能、いまは無料**：入口の判定を`canUseBranches(account)`の1か所に集め、いまは常にtrue。課金を始めたらここだけ変える。
- ログインしていない人は、分岐を見られるが作れない（「ログインすると自分の別行動を追加できます」と案内）。

**設計**：

- **DB**：`branches`（id・trip_id・account_id・date・start_time・end_time・title・created_at・updated_at）を新設し、`blocks.branch_id`（空文字＝みんなの予定）を足す（`migrations/0030_branches.sql`）。分岐は「日をまたがない1日の中の時間帯」（始まり＜終わり）。同じ人の分岐どうしは時間帯が重ならない（隣り合うのは可。別の人とは重なってよい）。日付は作ったあとで変えられない（変えたいときは作り直す。分岐の中の予定の日付が分岐に固定されているため）。
- **API**（`worker/src/index.js`。入力チェックと権限の判定は純粋関数`worker/src/branches.js`）：
  - `POST /trips/:id/branches`（本文 `{date, startTime, endTime, title?}`。ログイン必須・その旅行のアカウント参加者だけ）
  - `PATCH /branches/:id`（時間帯・タイトル。持ち主だけ）／`DELETE /branches/:id`（持ち主だけ。中の予定・記録・評価・いいね・コメントも1つのbatchで消す）
  - `POST /trips/:id/blocks`に`branchId`を付けると分岐の中の予定になる（持ち主だけ。日付は分岐の日に固定）。`PATCH/DELETE /blocks/:id`、記録の作成・更新・削除・移動（`/blocks/:id/entries`・`/entries/:id`・`/entries/:id/move`）は、分岐の中の予定なら持ち主だけ（他の人は403、ログインなしは401）。**みんなの予定の書き込みは今までどおり（トークン不要）**。分岐をまたぐ記録の移動は400（`different_branch`）。
  - `GET /trips/:id`が`branches`（持ち主のaccountIdと名前つき。メールは含めない）を返し、予定に`branchId`が付く。
  - 旅行の削除・アカウントの削除で、分岐と中身も消える。日程をずらす（`shiftDays`）ときは分岐の日付もずらす。旅行から「抜ける」だけでは分岐は消さない（自分が書いた記録を消さない、既存の方針と同じ）。
- **マイグレーション前にデプロイしても壊れない**：`GET /trips/:id`は`branches`テーブルが無ければ`branches: []`を返し（try/catch）、`blocks.branch_id`が無ければ全部「みんなの予定」として扱う。分岐を作ろうとしたときだけ503（`branches_not_ready`）。並べ替えの対象は`branch_id = ''`の予定だけ（列が無ければ全部）。サブリクエストは1リクエストにつき一定数のD1クエリ（分岐の削除は1つのbatch）。
- **画面側の持ち方**：旅行を開くと、予定を`state.blocks`（みんなの予定）と`state.branchBlocks`（分岐の中の予定）に分ける。時差・宿泊・並べ替えなど「みんなの予定」を前提にした既存の機能は`state.blocks`だけを見るので変えていない。**費用（総費用・精算・内訳）・アルバム・記録の検索は両方を見る**（分岐の中の費用も、ふつうの記録と同じく精算に入る。払った人・割る人はその明細で決まる）。
- **見せる並びは純粋関数（Core、`test/data.test.js`でテスト）**：`visibleBlocksForView`（人の道での旅行全体の予定。地図でふりかえる・動画・時差の計算が使う）、`dayTimelineItems`（その日のタイムライン。予定・カード・帯）、`blocksInBranchWindow`（時間帯に入るみんなの予定。開始ちょうどは含み終了ちょうどは含まない。時刻なしの予定は入れない）、`branchViewOptions`・`resolveViewAccountId`・`branchCardText`・`validateBranch`。カードと帯は「開始時刻以降で最初の時刻あり予定」の手前に入れ、自分の分岐の時刻なしの予定は帯の直後に並べる。
- **切り替えの記憶**：選んだ人は旅行ごとに端末（localStorage、`tabilog:branch-view:<tripId>`）に覚える。その人の分岐が無くなったら「みんな」に戻す。
- **人の道を見ているあいだ**は、みんなの予定の並べ替え（長押しドラッグ）を出さない（みんなの並びを変える操作なので「みんな」で行う）。別行動の中の予定は、記録の別の予定への移動も出さない。
- **時差**：分岐の中の予定の地図・到着地も`loadTripZones`で調べ、人の道を見るときはその道の並び（`activeBlocks()`）で時差を計算し直してから、ふりかえり・動画に渡す。

**画面**：旅行の上に切り替え（別行動がある旅行だけ）。タイムラインの「予定を追加」の下に「ここから別行動」（ログインなし・未参加には案内の文だけ）→シートで時間帯（始まり・終わり）とタイトル（任意）を入れる。作ったあとは自分の道に切り替わり、帯の「予定を追加」で予定フォームを開く（日付は固定、時刻は別行動の時間帯の中）。持ち主以外には、別行動の中の予定は見るだけ（編集・記録追加のボタンを出さない）。

**見送ったこと・割り切り**：

- 分岐の中の予定への音声・メモでのまとめ記録（作られるのは「みんなの予定」）。
- 他の人の分岐の記録に、★評価をつけること（評価は記録フォームから行うため、持ち主以外はフォームを開けない。必要になったら評価だけの入口を足す）。
- 時刻なしの「みんなの予定」は、別行動の間も消さずに残る（いつ起きたか分からないため）。
- 分岐の日付の変更、日をまたぐ分岐（深夜0時をまたぐ別行動は2つに分けて作る）。
- 分岐の中の予定の並べ替え（時刻順・時刻なしは作成順の自動並びのみ）。
- 旅行から抜けた人の分岐は残る（読めるが、参加し直すまで新しく作れない。すでにある分岐の予定は、セッションが有効なら持ち主なら直せる）。

**確かめたこと**：`node test/data.test.js`・`node worker/test/branches.test.mjs`・`node worker/test/branches-api.test.mjs`（`node:sqlite`の本物のSQLite上で、権限・重なり・削除の連鎖・マイグレーション前の挙動を通しで確認）。画面は、モックのAPIに差し替えたローカルのページ（本番のAPIは呼ばない）で、切り替え・カード・帯・シート・予定フォーム・ログインなし／未参加の表示を確認した。**確かめていない**：本番のD1・実機（iOS）、地図でふりかえる・動画の画面そのもの（渡す予定の選び方までをテストで確認）。
