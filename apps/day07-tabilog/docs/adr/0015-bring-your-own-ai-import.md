# 「自分のAIで整理して貼り付ける」無料インポートを追加する

音声・テキストメモをAIに整理させる既存の機能（`docs/adr/0002`）は運営側のOpenAI課金に乗っており、
無料利用は月10回まで（`docs/adr/0004`）に絞っている。決まった形（「10時 新宿」のように時刻で始まる行）
のメモは`parseMemo`でAIを使わず無料・無制限に取り込めるが、形が崩れたメモ（箇条書きだけ・時刻が
書かれていない、等）はAIでの整理に頼るしかなく、月10回を使い切ったユーザーには他の選択肢が無かった。
一方でユーザーの多くは、ChatGPT・Claude・Geminiなど**自分自身のAIアカウント**を既に持っている。運営側の
課金を経由せず、ユーザーが自分のAIに整理させた結果を貼り付けるだけで同じように取り込める第三の入り口を
用意する（2026-09-28）。

**決めたこと**：
- 「音声・メモでまとめて記録する」画面に3つ目の選択肢として追加する：「AIへのお願い文をコピー」ボタン
  （`Core.buildAiImportPrompt(trip)`が組み立てた文面をクリップボードへ）→ ユーザーが自分のAIに貼って
  自分のメモを足して実行 → 返ってきたJSONを「AIの答え（JSON）を貼り付け」欄に貼って「取り込む」。
- お願い文・JSONの形は、サーバー側のOpenAI呼び出し（`voicePrompt`/`multiDayPrompt`、
  `voiceBlocksSchema`/`multiDayBlocksSchema`、`worker/src/index.js`）と**同じBlockの形**
  （`date`・`time`・`label`・`category`・`transport`・`entry`{`episode`・`mapUrl`・`shopUrl`・
  `costItems`}）にそろえる。形を分けると読み取り側（`parseImportedBlocksJson`）を2種類保守する
  ことになり、サーバー側のプロンプトを直すたびにこちらも直し忘れるリスクがあるため、**1つの読み取り
  関数で両方をカバーできる形**を選んだ。
- 読み取りは`Core.parseImportedBlocksJson(text, trip)`という1つの純粋関数（`app.js`、
  `test/data.test.js`でテスト）に集約する。AIの答えには前置きの説明文・コードブロック
  （```` ```json ... ``` ````）が付くことが多いため、クォート・エスケープを見ながら文字列中の
  `{`/`}`（`[`/`]`）を数えて、**一番外側のJSON本体だけ**を取り出してから`JSON.parse`する。
  `{blocks:[...]}`と裸の配列`[...]`のどちらも受け付ける。
- 項目ごとに検証・補正し、`{blocks, warnings, errors}`を返す。`category`・`transport`が許された
  値でなければ安全側（`category`は`'other'`・`transport`は空文字）にフォールックして`warnings`に積む。
  複数日の旅行では、各項目の`date`が旅行期間内であることを必須にし、無い・範囲外ならその項目**だけ**
  取り込まず`errors`に積む（他の正しい項目はそのまま取り込む。1件のミスで全件やり直しにしない）。
  1日（または日程未設定）の旅行では`date`を省略でき、省略時は今開いている日タブになる。
- 費用の明細（`entry.costItems`）は、円の整数（`amount`）に加えて、海外通貨なら`currency`
  （ISO 4217、例："USD"）付きで受け付ける。ただし手入力の費用行（`docs/adr/0014`、`validCostItems`）
  と違い、`rate`（1`currency`あたりの円）まではユーザーの手元のAIに求めない（メモには書かれていない
  情報のため）。円換算はレートを入れるまで0円扱いになる（`costItemJpy`）が、amountそのもの
  （現地通貨の金額）は失われないので、あとで本人が費用の明細からレートを直す前提にした。
- 取り込み確定は、既存のAIなし取り込みエンドポイント`POST /trips/:id/memo-blocks`
  （`parseMemo`の「決まった形」取り込みと共通、`saveOrganizedBlocks`）にそのまま`blocks`を渡すだけ
  にし、**新しいエンドポイントは作らない**。ログイン・AIの利用回数（`memoRemainingThisPeriod`）の
  どちらとも無関係に使え、ログインしていなくても（旅行のURLさえ知っていれば）使える＝運営側の課金は
  一切発生しない。
- `saveOrganizedBlocks`は元々`entry.costItems`と`block.transport`を保存せず`"[]"`/`""`で固定して
  捨てていたため、この機能を作る過程で両方を保存するように直した（DBの列・スキーマは既存のまま。
  `blocks.transport`・`entries.cost_items`は元々ある列）。副作用として、既存の音声・テキストメモ
  経由の取り込みでもこの2項目が保存されるようになったが、そちらのAIプロンプト
  （`voicePrompt`/`multiDayPrompt`）はそもそも`transport`を求めていないため実質的な挙動は変わらない。
- 取り込み確定前に、件数・時刻・見出し・カテゴリ・金額・警告・省いた項目（エラー）のプレビューを
  必ず見せ、確認を押してから`POST`する（AIの言うことをそのまま無条件に保存しない、という他のAI機能
  と同じ姿勢。`docs/adr/0002`の「保存前の確認画面は挟まない」音声版とはここが異なる：あちらは運営側の
  AIの出力を一定信頼しているのに対し、こちらは形式の合っていないユーザー任意のJSONを扱うため）。

**避けたこと**：
- お願い文を「サーバー側のプロンプトの日本語をそのまま貼り替えるだけ」にすること。ユーザーの手元の
  AI（ChatGPT等）はこのアプリのコードを知らないため、`category`・`transport`の許可された値の一覧・
  JSON以外を出力しないこと・メモを貼る場所を、お願い文の中に明示する必要がある。
- 新しいサーバーエンドポイントを作ること。取り込み後の保存処理（Block・Entryを1トランザクションで
  作る、`saveOrganizedBlocks`）は決まった形のメモ取り込みと完全に共通のため、分ける理由が無い。
- 手入力の費用行と同じ`validCostItems`（`rate`必須）をそのまま流用すること。自分のAIに整理させた
  メモには為替レートまでは書かれていないのが通常のため、`rate`を必須にすると「費用の明細だけ全部
  エラーで消える」体験になってしまう。
