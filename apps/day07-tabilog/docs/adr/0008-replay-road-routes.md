# 地図でふりかえるの移動を、道路に沿った道のり（青い線）にする

「地図でふりかえる」の移動は2地点を直線で結んでいたが、「Googleマップで出る青い道のようなものを出すイメージ」と違っていた。あわせて「100倍速だと遅い」「場所を探すのに時間がかかる」という声もあった（2026-09-25）。

**決めたこと**：
- 車・タクシー・バス・徒歩・自転車の区間は、OpenStreetMapのルート検索（FOSSGIS運営の無料OSRM、`routing.openstreetmap.de`。車・徒歩・自転車の3種）で実際の道のりを取り、その上を移動アイコンが進む（`Core.pathAt`・`Core.replayStateAt`）
- 電車は線路のルートを出せる無料サービスが無いので直線、飛行機は今までどおり弧の点線。どちらも色は青に揃える
- 移動手段が入っていない移動も車とみなして道のりを出す（2026-09-26、「移動手段がなく移動しているのは基本車移動」という声より）。400km超は飛行機とみなす
- 道のりがそろうのを待たずに再生を始め、届いた区間から直線を道路沿いの線に切り替える（準備の待ち時間が長かったため）
- 見た目はGoogleマップの道のりに寄せ、白い縁取りの青（#1A73E8）。区間に入ったらこれから通る道のりを薄い青で先に見せ、進んだところまでを濃い青で伸ばす
- ルート検索は共用の無料サービスなので、Worker（`/route`）を通してUser-Agentを付け、同じルートは30日キャッシュする。1500km超の移動は調べない。取れなかった区間は直線のまま
- 速さは100倍速→500倍速→1000倍速（旅の1分＝0.06秒。2026-09-26にさらに速くした）。ただし移動の演出は距離・時間にかかわらず1区間2秒にした（香港→ニューヨークの飛行機が長すぎたため）。着いた地点の写真は1枚2.5秒ずつ見せる
- 場所の準備を速くする：座標入りのリンクなどNominatim（1秒1回まで）を使わずに分かるものは全部同時に聞き（`/geocode?quick=1`）、住所・店名から探すものだけ1.1秒ずつ空けて聞く。以前は全部を1.1秒ずつ空けていた

**見送ったこと**：電車の線路に沿った道のり（有料の経路APIが要る）、Googleのルート検索（APIキーと費用が要る）。

**2026-09-26 追記（不具合修正）**：

- 飛行機の区間も、道のりが届くのを待たず「これから通る道」（弧の全体）を最初から薄い青で見せるようにした。
  以前は飛行機だけ`plan`（これから通る道のプレビュー）を作っていなかった。弧の点はCore側（`planeArcPath`）で
  区間が決まった時点にあらかじめ作っておく（ネットワークで調べる必要が無い純粋計算のため）。
- アイコンの位置と線の描画が同じ弧をたどるよう、飛行機の区間も車と同じ`leg.path`の仕組みに統一した
  （以前はアイコン用の`arcLatLng`と線用のサンプリングが別々の実装で、日付変更線をまたぐ移動などでずれうる
  作りだった）。日付変更線をまたぐ移動（ハワイ⇄東京など）は、経度の変化が短い方（180度以内）になるよう
  `planeArcPath`で経度をあらかじめ連続にしてから弧を作る。
- 地図がズーム・移動アニメ中（`flyToBounds`など）に線（SVGレンダラーの座標）を更新すると、アニメが終わる
  （`moveend`/`zoomend`）までタイルとずれた位置に描かれてしまうLeafletの既知の癖があり、「区間の変わり目で
  地図がずれ、青い線が追いつかない」の原因になっていた。アニメ中は線の更新を止め（乗り物のアイコンは通常の
  マーカーなので動かし続けてよい）、アニメが終わったら1回描き直すようにした。
- 車ルートが直線距離よりずっと長い（2.5倍を超え、かつ+1.5km以上長い）ときは、歩行者専用の目的地（階段など）
  に大回りしている疑いとみなし、徒歩ルートで調べ直す。それでも長ければ直線に戻す
  （`Core.isRouteDetourTooLong`。リオデジャネイロ大聖堂→セラロン階段で発覚）。
- 移動手段が入っていない、とても近い移動（1.5km未満）は車ではなく徒歩とみなす（同じく大回り対策）。
- 「コルコバードの丘への道が抜けている」については、ルート検索が無い移動手段（電車など）でも
  区間の間ずっと座標が求まり直線を描けることをテストで確認した。実際に抜けて見えるのは、地図のURLが
  無い・展開できない予定（下記のS2セルID対応で一部解消）が「場所の分からない予定」として扱われ、
  その前後の場所を直接結んでしまうデータ側の問題である可能性が高い。
- 時差バナー（「時差 …」）は、着陸（到着）の瞬間に初めて切り替わり、飛行中・出発時には出ないことをテストで確認した
  （`replayStateAt`は、到着予定の`r`に達するまで出発地の時差のままにしている。既存の実装で問題なし）。
- （`/geocode`）Googleマップの「共有」から来る、店名も座標も入らないリンク
  （`data=!4m2!3m1!1s0x…:0x…`や`ftid=0x…:0x…`）は、コロン前の16進数がその場所のS2セルIDになっていることが
  多いと分かったため、`worker/src/geo-decode.js`にデコーダを追加し、座標が直接読めないときの手がかりとして使う
  （店名・座標のパターンに次ぐ優先度、文字列検索より先）。地図でふりかえる以外の「地図のURL」全般に効く。
