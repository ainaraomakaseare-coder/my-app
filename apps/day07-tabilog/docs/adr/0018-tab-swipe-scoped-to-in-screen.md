# タブバーの4画面を横スワイプで行き来する仕組みを廃止し、画面内の横スワイプだけに絞る

a4f2949（2026-09-29）で、ボトムタブバーの4画面（マイログ・旅先一覧・旅の足跡・プロフィール）を横スワイプで行き来できるようにし、あわせて「行ったことある旅先」の国内⇄海外スワイプ・マイログの「評価したもの」カテゴリスワイプにも「境界（最初/最後）でさらに同じ向きへスワイプしたら、隣のタブへ流れる」というフォールスルーを付けた。

同日、TestFlight 98でオーナーから2件のフィードバックが来た。

1. 「（旅先一覧の国内⇄海外の）スワイプで国内海外を移動できるんだけど操作性がかなり悪い。地図を押しているとスワイプできない気がする」
2. （続けて）「タブ同士がスワイプで切り替わるのはやめてほしい（マイログ→旅先一覧なども含めて全部）」

**決めたこと**：

- **タブ同士の行き来は、ボトムタブバーのタップだけにする**。`initTabSwipe`をhome・profile画面には登録せず、マイログ・旅先一覧の画面内スワイプからも隣のタブへのフォールスルーを削除した（`goToAdjacentTabBySwipe`・`adjacentTabName`・`TAB_ORDER`は使い道が無くなったため削除）。境界でさらに同じ向きへスワイプしても、指を離すとラバーバンドで跳ね返るだけにする。
- **地図（SVG）の上から始まったタッチもスワイプの対象にする**。以前は`startsOnHorizontalScroller`が「SVGの上から始まったタッチは全部対象外」という決め打ちを持っており、これが「地図を押しているとスワイプできない」の直接の原因だった（地図がページの大半を占めるため、ほぼ画面全体でスワイプが効かない状態になっていた）。日本地図・世界地図はどちらも静的なSVG（パン・ズームなし）で、領域タップは`<title>`のあるパス要素へのクリックであり移動を伴わないため、横スワイプの開始点として扱っても安全と判断した。除外対象は「実際に横スクロールできる要素」（`scrollWidth>clientWidth`かつ`overflow-x: auto/scroll`。マイログのカテゴリピル行など）だけに絞った。
- **タップとスワイプの取り違えを防ぐ・見た目を軽くする**ため、向き・コミットの判定を純粋関数`Core.decideSwipe(dx, dy, dt)`に切り出した。横方向は|dx|が|dy|の1.2倍を超えたときだけ、コミットは40px以上動くか、短くても素早い（20px以上・0.35px/ms以上のflick）動きのときだけ。地図の領域タップ（`wireVisitedMapRegions`）とスワイプが同時に反応しないよう、スワイプがコミットした直後の一瞬だけ合成clickを無視するガードを入れた。
- **ドラッグ中は指に追従（`translateX`）し、境界（もう先がない）ではラバーバンドで重くする**。指を離すと現在地から0へease-out（約200ms）で収まる（`prefers-reduced-motion`のときはアニメーションしない）。`touch-action: pan-y`を対象領域（`.screen[data-screen="visited"]`・`#mylogList`）に付け、縦スクロールはブラウザのネイティブ処理のまま、横方向のジェスチャーだけJSに渡るようにした。`touch-action`はCSSの継承の都合上、祖先要素に付けると子孫では上書きできない（MDN）ため、横スクロールする兄弟要素（`.mylog-tabs`）を含まない、より内側の要素（画面全体ではなく`#mylogList`）に絞って付けている。

**避けたこと**：フォールスルー自体を残しつつ閾値だけ緩める対応（オーナーは「地図が押しにくい」だけでなく「タブ同士が意図せず切り替わる」ことそのものを問題視していたため、フォールスルーは丸ごと無くした）。`startsOnHorizontalScroller`から地図を除外したまま、地図の余白だけをスワイプ領域にする対応（地図がページの大半を占めるレイアウトでは効果が薄い）。
