# たびログ

旅行の思い出を、写真とともに「日ごと・時間ごとのきろく」として振り返るアプリです。いつからいつまで・だれと・どこへ・どこに泊まって・いくらかかったかを、時系列の記録としてまとめます。

```
open index.html
```

**このアプリは、これまでのDAY（NHKチンチロ・輸入ブラックジャック・ドラマ王・人狼・おもいでWiki）と違い、保存先が端末の中（localStorage）ではなくサーバー（データベース）です。** 旅行のURLを家族に送るだけで、送られた側もその場で見たり書き足したりできます。かわりに `worker/README.md` の手順でサーバーを一度公開する必要があります。

## データの考え方：大項目と小項目

1つの旅の記録は、2階層でできています。

- **大項目（予定）**：「10:00　那覇空港に到着」のような、いつ・どこで・何をする時間か。日付・時間・見出し・種類（観光／食事／宿泊／移動／その他）を持ちます
- **小項目（記録）**：その予定のときの、一人ひとり（またはサブグループ）の記録。エピソード・写真・ひとこと・費用の明細・待ち時間・地図のURL・お店のHP・記録した人を持ちます

**別行動した場合は、同じ大項目の下に小項目をもう1つ足すだけで表現できます。** たとえば「15:00 首里城公園に到着」という1つの大項目の下に、父チームの記録と母チームの記録を2つ並べる、という形です。全員が常に同じ行動とは限らないため、この形にしています。

## できること

- **旅行を作る**：タイトル・出発日〜帰着日・だれと行ったかを登録すると、日程から自動で「1日目」「2日目」…の日タブができます
- **日ごとのきろく**：選んだ日の予定を時間順に並べ、それぞれに1件以上の記録をぶら下げます
- **費用の明細**：記録ごとに「そば ¥800」「飲み物 ¥400」のように費用の内訳を何行でも追加でき、自動で合計します。旅行全体の総費用も自動で合計します
- **宿泊の記録**：予定の「種類」を「宿泊」にすると、そのカードだけ色を変えて目立たせます。旅行全体の宿泊先も一覧の上部にまとめて表示します
- **地図・お店のHP・待ち時間**：記録ごとにGoogleマップなどのURL、お店・施設のHPのURL、待ち時間を添えられます
- **詳細**：エピソード・ひとことのほかに、もっと長く書きたいことのための「詳細」欄があります（持ち物・注意点・裏話など）
- **共有して招待する**：旅行の詳細画面の共有ボタンで、今開いているURL（`?trip=旅行のID` を含む）をコピーできます。Googleログインを設定した場合は、このURLを開いた人もログインが必要になります（下記「Googleログインについて」参照）
- **写真**：選んだ時点で自動的に縮小・圧縮してからサーバーへアップロードします（長辺1280px・JPEG品質72%程度）
- **動画**：1本あたり最大50MBまで（圧縮はしません）。写真と同じ「＋ 写真を追加する」の下に、動画専用の追加ボタンがあります

## iOSアプリ化について

このWeb版をそのままiOSアプリの器に包み、App Store（TestFlight）に送る仕組みを `apps/day07-tabilog-ios/` に用意しています。手順・必要な費用（Apple Developer Program 年間99ドルが必須）は `apps/day07-tabilog-ios/README.md` を参照してください。

## 共有の仕組みについて（重要）

旅行ごとに発行される `trip_xxxxxxxx` というIDを含むURLを知っている人が読み書きできます（Googleドキュメントの「リンクを知っている全員が編集可」に近い方式です）。家族・少人数のグループでURLを送り合って使うことを想定した、簡易的な共有です。不特定多数に公開するような使い方はおすすめしません。

Googleログインを設定すると、このリンクを開いた人はGoogleアカウントでのログインも必要になります。ログインした本人の名前が「記録した人」に自動で入るようになります（手で書き直すこともできます）。**リンクの共有自体は今までどおりで、招待の仕組みが変わるわけではありません。** 「＋ メンバーを招待」ボタンも同じ意味（このURLをコピーして送る）のまま残しています。

## Googleログインについて（任意設定）

Googleアカウントでのログインを追加できます。**設定しなくても、今までどおりリンク共有だけで使えます。**（`index.html` の `tabilog-google-client-id` メタタグが空のままなら、ログイン機能自体が無効になります。）

このログインは、**サーバー側でトークンを検証しない、簡易的な仕組みです**（ブラウザの中だけで完結します）。低リスクな家族向けアプリという前提で、「誰が記録したか」を自動入力するための本人確認として使っています。銀行アプリのような厳密な認証ではない点をご理解ください。

### 設定手順

1. https://console.cloud.google.com/ を開き、新しいプロジェクトを作成（または既存のものを使う）
2. 「APIとサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
3. 初回は「OAuth同意画面」の設定を求められます。ユーザーの種類は「外部」でよい（テスト段階では自分・家族のメールアドレスを「テストユーザー」に追加しておく）
4. アプリケーションの種類：「ウェブ アプリケーション」
5. 「承認済みの JavaScript 生成元」に、公開先のURLを追加：
   - `https://ainaraomakaseare-coder.github.io`
   - ローカルで試す場合は `http://localhost:ポート番号` も追加（`npx serve -l 5000` のようにポートを固定すると管理しやすい）
6. 作成すると「クライアントID」（`〇〇〇.apps.googleusercontent.com` の形）が発行されるので、`index.html` の `tabilog-google-client-id` メタタグの `content` に設定する

費用は無料です（Google Cloudのプロジェクト作成・OAuthクライアントID発行自体に料金はかかりません）。

## Appleでサインインについて（任意設定・App Store公開時はほぼ必須）

Appleの審査ルール（App Store Review Guideline 4.8）上、**Googleログインなど他社のログイン手段を提供する場合は、Appleでのサインインも選択肢として用意する必要があります。** 家族内だけの利用（TestFlightの内部テストのみ）であれば無くても進められますが、App Storeで一般公開するなら実質必須です。

設定しなくても、今までどおりリンク共有・Googleログインだけで使えます（`index.html` の `tabilog-apple-client-id` メタタグが空のままなら、Appleログインのボタン自体が表示されません）。こちらもGoogleログインと同様、サーバー側で検証しない簡易的な仕組みです。

### 設定手順（Apple Developer Program登録後に行う）

1. https://developer.apple.com/account/resources/identifiers/list/serviceId を開く
2. 「+」で新しい**Services ID**を作成（例：識別子 `com.hiroyaapps.tabilog.web`。iOSアプリ本体のBundle ID `com.hiroyaapps.tabilog` とは別物）
3. 作成したServices IDの設定画面で「Sign in with Apple」を有効化し、「Configure」から以下を登録
   - Primary App ID：iOSアプリ本体のBundle IDを選択
   - Domains and Subdomains：`ainaraomakaseare-coder.github.io`
   - Return URLs：`https://ainaraomakaseare-coder.github.io/my-app/apps/day07-tabilog/`
4. ドメインの所有確認のため、この画面で「Download」できるドメイン確認用ファイルを、このリポジトリのルート直下 `.well-known/apple-developer-domain-association.txt` として保存する（GitHub Pagesで公開されているドメインのルートに置く必要があるため）
5. 発行されたServices ID（`com.hiroyaapps.tabilog.web`）を、`index.html` の `tabilog-apple-client-id` メタタグの `content` に設定する

費用は無料です（Apple Developer Programの年会費に含まれており、追加の費用は発生しません）。

## サーバーについて

写真やデータの保存にはCloudflare WorkerとD1（データベース）・R2（写真の保存）を使います。公開手順・費用の目安（無料枠に収める方針）は `worker/README.md` を参照してください。**サーバーを公開して `index.html` の `tabilog-api-endpoint` メタタグにURLを設定するまでは、旅行の保存はできません**（トップ画面にその旨の案内が出ます）。
