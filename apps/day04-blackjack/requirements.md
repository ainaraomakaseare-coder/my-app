# 輸入ブラックジャック 要件定義（確定版）

いただいた要件定義書に、ヒアリングで確定した項目を反映したもの。カジノのブラックジャックとは別物で、**21に近づけるという勝利条件だけを借りた2人用の読み合いゲーム**として設計している。ヒットもスタンドもディーラーもなく、手札は最初から最後まで4枚のまま。核はトレード。

ゲーム名「輸入ブラックジャック」は仮称。`blackjack.html` の `<title>` と `.logo` の2箇所を書き換えれば変わる。

## 1. 札

- トランプの A〜10 の40枚。J・Q・K・ジョーカーは使わない
- A は 1 として数える（11 として扱う処理はしない）
- 赤（♥ ♦）20枚 / 黒（♠ ♣）20枚を、2人が1組ずつ持つ
- **どちらの組も 1〜10 が2枚ずつで、構成はまったく同じ。運の要素はゼロ**で、色は持ち主を見分ける印でしかない

## 2. 初期手札

- 自分の20枚**すべてを見た上で自由に**、合計21以下になる4枚を選ぶ（山のシャッフルは先攻決定のドロー順を決めるためだけに使う）
- 4枚を超えて選べない。4枚で22以上になったときは「合計が21を超えています」と出して確定させない
- **選んだ順がそのまま並び順**になる。システムは並べ替えない
- 相手にも同じ位置で見える。位置に意味を持たせるかどうかはプレイヤーの裁量で、並べ方そのものがブラフの道具になる

## 3. 公開札

- 双方が4枚を決めたあと、**相手の**4枚から1枚を指名して表向きにさせる（裏向きの位置しか見えない状態で選ぶ）
- 公開は「枠」に付く。トレードで中身が入れ替わっても、その枠は公開のまま
- 公開されている札もトレードに出せる

## 4. 先攻決定

- 手札に使わなかった16枚から1枚ずつ引く。大きい方が先攻か後攻かを選ぶ
- 同じ数字なら引き直す
- 引いた札は表向きのまま脇に置き、局の終わりまで残す。トレードには関わらない

## 5. アクション

- 先攻 → 後攻の順に、チェックかトレードを宣言する
- **トレードは双方が手札から1枚ずつ伏せて出し、同時に交換する。宣言していない側は断れない**
- 出す札は先攻から選ぶ
- 1局の交換は最大2回

| 先攻 | 後攻 | 交換回数 |
|---|---|---|
| チェック | チェック | 0 |
| チェック | トレード | 1 |
| トレード | チェック | 1 |
| トレード | トレード | 2 |

補足：

- 交換で22以上になるのは許容する。これがゲームの緊張の源
- 1回目にもらった札を2回目に出せる。1回目に自分が渡した札が返ってくるのも許す
- 交換で相手色の札が手札に混ざる。色はそのまま表示する
- 交換した2枚は、この時点で双方に見える（自分が渡した札も、受け取った札も、両者が知っている）。したがって交換結果の画面は2人で同時に見てよい
- 結果として、自分が渡した札は相手の手札のどこにあるか分かる。「相手について分かっていること」として画面に出す

## 6. 勝敗

判定の順序：

1. バーストの有無を確認する（22以上がバースト）
2. 片方だけバースト → バーストしていない方の勝ち
3. ともにバースト → **21からの超過が少ない方の勝ち**
4. ともに21以下 → 合計が大きい方の勝ち
5. 合計が同じ → 大きい札から順に4枚まで比較し、大きい方の勝ち
6. 4枚すべて同じ → 引き分け

- **バーストしていても比較の向きは反転させない。**「バーストのときだけ逆」という例外を作らないため
- スートは勝敗に使わない

## 7. 局の外側

- 何局でも続けられる。終了条件は設けず、通算成績（各人の勝ち数と引き分け数）を出す
- 1局ごとに赤黒を入れ替える
- 先攻決定は毎局引き直す
- 途中経過は localStorage に保存し、リロードしても続きから遊べる。再開時は必ず受け渡し画面から始める

## 8. 端末の受け渡し

1台を2人で回すため、伏せた札が出る画面では受け渡しを挟む。

- 挟むのは**端末の持ち手が実際に変わるときだけ**。同じ人が続けて操作する場面（トレードを宣言してそのまま出す札を選ぶなど）では省く
- 1局あたり6〜9回
- 先攻決定の画面と結果画面は2人で同時に見てよい

> **ヒアリング時からの変更点が1つある。**「宣言（チェック/トレード）は公開情報だから受け渡し不要」としていたが、**宣言する本人は自分の4枚を見ないと決められない**ため、宣言画面にも受け渡しが必要になった。宣言の結果が公開情報であることと、宣言するために手札を見る必要があることは別の話だった。

## 9. 実装

- `blackjack.html` 1枚。ビルドなし、外部ライブラリなし
- 想定端末はスマートフォン縦持ち。PC でも崩れない
- 既存の NHKチンチロ と同じ墨色ベースの配色。赤の組は朱、黒の組は墨がそのまま嵌る
- 演出は札のめくりと交換の表示のみ。物理演算と効果音は入れない。`prefers-reduced-motion` に対応
- 状態遷移: `select → reveal → draw → act →(trade → swap)→ act →(trade → swap)→ result`

## 10. バリデーション

- 4枚より多く選べない / 初期手札の合計22以上は確定できない
- 自分の山にない札は選べない
- トレードで出せるのは1枚だけ、自分の手番以外は操作できない
- 交換は最大2回を超えない
- 勝敗判定後に手札は変わらない
- 伏せた札が、見てはいけない相手の画面に出ない

## 12. 決めごとの根拠（要確認事項への回答）

| | 内容 | 決定 | 理由 |
|---|---|---|---|
| Q1 | 両者バースト | 21との差が小さい方の勝ち | 引き分けにすると、劣勢側が捨て身のトレードで引き分けに逃げる手が強くなりすぎる |
| Q2 | 先攻決定が同数 | 引き直す | スートに優劣という概念を持ち込まずに済む |
| Q3 | トレードで22以上 | 許容する | ゲームの緊張の源。むしろ本質 |
| Q4 | 公開札のトレード | 出せる | 出せないと「見えている札を押し付ける」駆け引きが消える |
| Q5 | 交換後の公開状態 | 枠が公開を維持する | 公開が消えると、公開札を出すだけで情報を消せてしまい、指名する意味が薄れる |
| 追加 | 手札の並び順 | 選んだ順のまま、自動整列しない | 数字順に整列させると位置が大小を漏らす。選んだ順を尊重すればブラフの道具になる |
| 追加 | 同点時のカード比較 | バースト時も反転させない | 例外を作るとルールが濁る |
