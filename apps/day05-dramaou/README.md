# ドラマ検定

好きなドラマの題名を入れると、その作品の問題が10問出ます。どこまで細部を覚えているかで称号が変わります。

```
open apps/day05-dramaou/index.html
```

HTML1枚で動き、ビルドもサーバーも要りません。ただし**問題は日本語版 Wikipedia から取ってくるので、通信できる環境が要ります**。

出題のしかたは2通りあります。既定は記事の表から機械的に作る方式で、鍵も費用も要りません。**AIに問題を作らせる**を入にすると、記事の文章を Claude に読ませて、物語の中身を問う問題を足します（費用がかかります。下の「AIに問題を作らせる」参照）。

## どこから問題を作っているか

日本語版 Wikipedia の記事 HTML を1回取得し、そこから2種類の材料を抜きます。

| 材料 | どこから | 何が取れるか |
|---|---|---|
| infobox | `table.infobox` の各行 | 放送局・放送期間・話数・脚本・演出・出演者・音楽・原作 |
| 各話表 | `table.wikitable` のうち話数の列を持つもの | 各話のサブタイトル・放送日・視聴率 |

Wikidata ではなく記事本文を読んでいるのは、**日本のドラマについては Wikidata より記事のほうが圧倒的に詳しい**からです。とくに各話のサブタイトルと視聴率は Wikidata にほぼ入っていません。

使う API は2つだけです。

```
action=query&generator=search   … 題名から候補を引く
action=parse&prop=text          … 記事本文の HTML を取る
```

どちらも `origin=*` を付けているので、API キーなしで、ブラウザから直接呼べます。

## 出題

10問を難しさの3層から組みます。難しい層ほど配点が重く、そこを当てられるかがマニア度になります。

| 層 | 配点 | 問数 | 中身 |
|---|---|---|---|
| やさしい | 1点 | 3問 | 主要な配役、放送局、放送開始年、全何話 |
| ふつう | 2点 | 4問 | 配役の裏返し、出演していないのは誰、原作 |
| 難しい | 3点 | 3問 | 第N話のサブタイトル、そのサブタイトルは第何話、視聴率、放送日 |

**満点は実際に出した問題の重みの合計**です。材料が足りず10問に届かない作品があるので、固定の点数にはしていません。材料が揃えば 3×1 + 4×2 + 3×3 = 20点になります。

層の呼び名は難しさです。以前は「基本／制作／各話」と中身で呼んでいましたが、材料が足りないときに層をまたいで埋めることがあり、AI出題が混ざるとさらに合わなくなるため、難しさの呼び名に改めました。

**ダミーの選択肢**をどう選ぶかで問題の質が決まります。

- サブタイトルは**同じドラマの別の話**から取ります。どれも本物なので、うろ覚えでは引っかかります。
- 人物は年代別のプールから、**対象作と20年以上離れた年代**の人を選びます。「実はその人も出ていた」という誤判定を避けるためです。
- 数字（年・話数・視聴率）は正解の前後から散らします。
- 放送局は主要局から。

同じ材料を問う設問が並ぶと繰り返しに見えるので、上限を置いています。**同じテンプレから2問まで、同じ材料の系統（役名と俳優／出演者／サブタイトル）から4問まで**。ただし材料の薄い作品では10問に届かなくなるので、そのときだけ控えから足します。控えを使っても、同じテンプレは3問・同じ系統は5問を超えません。

問題が少ないことと繰り返しに見えることを比べて、少ないほうが困ると判断しています。

## AIに問題を作らせる

表や箱書きから作る方式では、**そこに載っている事実しか問えません**。「誰が何を演じたか」は問えても、「物語の中で何が起きたか」は問えない。そこを埋めるのがこの仕組みです。

記事から「あらすじ」「登場人物」といった節の文章だけを抜き（最大12,000字）、Claude に読ませて設問を作らせます。返り値は JSON Schema で形を固定しているので、自由文を切り出す処理は要りません。

**AIの出力はそのまま出しません。** 受け取ってから機械で検査し、落ちたものは捨てます。

- 選択肢がちょうど4つで、重複していないか
- 正解が選択肢の中に文字列として在るか
- 問題文に答えが漏れていないか
- 正解だけ長さが浮いていないか
- 根拠（記事のどこから作ったか）が書かれているか

捨てたぶんは今までのテンプレート出題で埋めます。**AIが1問も通らなくても、鍵が無くても、テンプレート出題だけで成立します。** 通信に失敗したときも同じで、理由を結果画面に出したうえで出題は続きます。

各設問には根拠を書かせていて、これは結果画面の振り返りにそのまま出ます。根拠を必須にすると、記事に無いことを書きにくくなります。

### APIキーと費用

**キーはリポジトリに置きません。** 遊ぶ人が画面から入れて、その端末の `localStorage` にだけ保存します。入力欄は伏せ字で、消すボタンもあります。

ブラウザから直接 `api.anthropic.com` を呼ぶために `anthropic-dangerous-direct-browser-access: true` を付けています。名前のとおり、キーがブラウザに載ることを承知したうえで付けるものです。この作りが成立するのは「**遊ぶ人が自分のキーで、自分の分だけ払う**」形だからで、作った人のキーを埋め込んで配ると他人の遊んだ分まで請求が来ます。

公式SDKを使っていないのは、ビルド無しの1枚HTMLに npm パッケージを置く場所が無いためです。素の `fetch` で呼び、必要なヘッダは自分で付けています。

モデルは画面で選べます。既定は Opus 5 で、1回の出題でおよそ $0.12。Sonnet 5 と Haiku 4.5 も選べます。**実際にかかった額は、返り値の `usage` から計算して結果画面に出します。** 見えないまま課金される作りにはしていません。金額はドルのまま出します（換算レートを勝手に決めない、という `docs/CLAUDE.md` の決めごとに従っています）。

「同じドラマでもう一度」ではAIを呼び直しません。一度作らせた問題を並べ替えて使い回すので、遊び直しで二重に課金されることはありません。

出題の考え方そのものは `.claude/skills/quiz-design/` に Skill として置いてあります。実装とSkillで検査の基準が食い違わないよう、同じ規則を書いています。

## 記事によっては問題が作れないこと

infobox が無い記事や、各話表の列名が変わっている記事では材料が揃いません。読み込み中に**何が取れて何が取れなかったか**を印で出しているので、原因を追えます。4問も作れない場合はその旨を出して止まります。

材料が足りないテンプレは黙って見送る作りなので、一部が欠けても残りで出題は成立します。

## 公開

GitHub Pages に置く場合、`apps/day05-dramaou/` がそのまま URL になります。

```
https://ainaraomakaseare-coder.github.io/my-app/apps/day05-dramaou/
```

Artifact として公開すると CSP が外部通信を全部止めるため、**この作りでは動きません**。問題を取りに行けなくなります。

## テスト

```
node test/quiz.test.js     # 文字列の整形・出題の組み立て・AI出力の検査・採点（802件）
node test/quiz.ui.js       # 実ブラウザでの画面の流れとパーサ（127件、要 playwright）
```

`quiz.test.js` は `index.html` の `PURE-BEGIN` から `PURE-END` までを切り出して node 上で直接動かします。この範囲は DOM にも通信にも触れないので、そのまま試験台に載せられます。

`quiz.ui.js` は Wikipedia と Anthropic への通信を両方とも差し替えるので、**ネットにつながっていなくても、APIキーが無くても、費用もかけずに走ります**。実際の記事に近い HTML を食わせて infobox と各話表の読み取りを見るほか、AI出題では送っているヘッダと本文、壊れた設問が捨てられること、失敗したときテンプレート出題に落ちること、遊び直しでAIを呼び直さないことまで見ています。
