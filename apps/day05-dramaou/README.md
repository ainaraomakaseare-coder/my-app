# ドラマ検定

好きなドラマの題名を入れると、その作品の問題が10問出ます。どこまで細部を覚えているかで称号が変わります。

```
open apps/day05-dramaou/index.html
```

HTML1枚で動き、ビルドもサーバーも要りません。ただし**問題は日本語版 Wikipedia から取ってくるので、通信できる環境が要ります**。

**お金はかかりません。** APIキーも要りません。問題は全部この1枚のHTMLの中で組み立てています。

15作品ぶんの**作り置きの問題**を持っていて、その作品では記事から作った問題と混ぜて出します。

## どこから問題を作っているか

日本語版 Wikipedia の記事 HTML を1回取得し、そこから2種類の材料を抜きます。

| 材料 | どこから | 何が取れるか |
|---|---|---|
| infobox | `table.infobox` の各行 | 放送局・放送期間・話数・脚本・演出・出演者・音楽・原作 |
| 各話表 | `table.wikitable` のうち話数の列を持つもの | 各話のサブタイトル・放送日・視聴率 |

Wikidata ではなく記事本文を読んでいるのは、**日本のドラマについては Wikidata より記事のほうが圧倒的に詳しい**からです。とくに各話のサブタイトルと視聴率は Wikidata にほぼ入っていません。

使う API は2つだけです。

```
action=query&generator=search   … 題名から候補を引く
action=parse&prop=text          … 記事本文の HTML を取る
```

どちらも `origin=*` を付けているので、API キーなしで、ブラウザから直接呼べます。

## 出題

10問を難しさの3層から組みます。難しい層ほど配点が重く、そこを当てられるかがマニア度になります。

| 層 | 配点 | 問数 | 中身 |
|---|---|---|---|
| やさしい | 1点 | 3問 | 主要な配役、放送局、放送開始年、全何話 |
| ふつう | 2点 | 4問 | 配役の裏返し、出演していないのは誰、原作 |
| 難しい | 3点 | 3問 | 第N話のサブタイトル、そのサブタイトルは第何話、視聴率、放送日 |

**満点は実際に出した問題の重みの合計**です。材料が足りず10問に届かない作品があるので、固定の点数にはしていません。材料が揃えば 3×1 + 4×2 + 3×3 = 20点になります。

層の呼び名は難しさです。以前は「基本／制作／各話」と中身で呼んでいましたが、材料が足りないときに層をまたいで埋めることがあり、AI出題が混ざるとさらに合わなくなるため、難しさの呼び名に改めました。

**ダミーの選択肢**をどう選ぶかで問題の質が決まります。

- サブタイトルは**同じドラマの別の話**から取ります。どれも本物なので、うろ覚えでは引っかかります。
- 人物は年代別のプールから、**対象作と20年以上離れた年代**の人を選びます。「実はその人も出ていた」という誤判定を避けるためです。
- 数字（年・話数・視聴率）は正解の前後から散らします。
- 放送局は主要局から。

同じ材料を問う設問が並ぶと繰り返しに見えるので、上限を置いています。**同じテンプレから2問まで、同じ材料の系統（役名と俳優／出演者／サブタイトル）から4問まで**。ただし材料の薄い作品では10問に届かなくなるので、そのときだけ控えから足します。控えを使っても、同じテンプレは3問・同じ系統は5問を超えません。

問題が少ないことと繰り返しに見えることを比べて、少ないほうが困ると判断しています。

## 地の文から問題を作る

infobox と各話表から作れるのは、**そこに載っている事実**だけです。「誰が何を演じたか」は問えても「物語の中で何が起きたか」は問えません。そこを埋めるために、記事の**地の文**（あらすじ・登場人物の説明）からも出題します。

| 出題 | 材料 | 例 |
|---|---|---|
| 説明文から役名 | 人物紹介の一行 | 「本作の主人公。東京育ちの内気な女子高生で、北三陸で海女を目指す」と説明されるのは？ |
| 人物の関係 | 説明文の「◯◯の母」 | 天野アキ の母にあたるのは？ |
| あらすじの空欄補充 | あらすじの一文 | 「〇〇〇は北三陸鉄道の駅長として、地元を盛り上げようと奔走する」の〇〇〇は？ |

どれも**記事に書いてある本物の文**が根拠なので、事実を作り出す余地がありません。ダミーは同じ作品の別の人物から取るので、作品を知らないと消去法では潰せません。

### 呼び名の揺れ

ここで必ず一度つまずきます。記事は人物紹介で「天野アキ」と書き、あらすじでは「アキ」と書きます。**フルネームだけで本文を探すと、一度も当たりません。**

呼び名の候補（フルネーム・姓・名）を並べ、**その呼び名を含む人物が一人だけのものだけ**を使います。「天野アキ」「天野春子」「天野夏」がいるので「天野」は誰にも当てられず捨て、「アキ」「春子」は使います。

伏せるときは長い呼び名から先に処理します。「アキ」を先に伏せると「天野アキ」が壊れて「天野〇〇〇」になるためです。

空欄補充は、**その文に出てくる人物がちょうど一人のときだけ**作ります。二人以上いると伏せた先が一意に決まりません。

### なぜAIを呼ばないのか

一度は Claude API を呼んで作らせる形にしましたが、**遊ぶたびに課金される**ので取りやめました。誰かに配るものでは、鍵を埋め込めば他人の遊んだぶんが自分の請求になり、鍵を入れさせれば遊ぶ人の負担になります。上の3つで「物語の中身を問う」という目的は足りています。

判断の基準は `.claude/skills/quiz-design/` に Skill として置いてあります。実行時にAIを呼ぶ必要が本当にある場合の作法もそちらに書いてあります。

## 作り置きの問題

記事のどこを読んでも作れない問題があります。決めぜりふ、設定の核、作品の仕掛け——「半沢が繰り返した決めぜりふは？」は infobox にも各話表にも書いていません。

そこで2000年以降の代表作15作品について、**1作品2問ずつ、合計30問を先に用意してあります**。入口に並ぶ作品名がその15本です。

| | |
|---|---|
| 半沢直樹 | 家政婦のミタ |
| 逃げるは恥だが役に立つ | あまちゃん |
| ごくせん | 白い巨塔 |
| HERO | 花より男子 |
| JIN-仁- | アンナチュラル |
| カルテット | silent |
| 鎌倉殿の13人 | 電車男 |
| ドクターX | |

**順位ではありません。** 人気順の出典を取れないので、順位は名乗りません。代表作から選んだ15本です。

置き方の決めごと:

- **記事から作れる問いは置かない。** 「誰が演じたか」「放送局は」は記事から作れるので、作り置きに入れる意味がない
- **1作品2問まで。** 作り置きだけで10問を埋めない。残り8問は記事から作る
- **必ず出す。** 記事の材料が豊富な作品でもテンプレート同士の取り合いに負けないよう、作り置きは優先して入れる。手で作った問題が出ないのでは置いた意味がない
- **正解の位置は毎回混ぜる。** 表に並べた順のまま出すと数問で気づかれる
- **入口に並ぶ作品名は、作り置きの表から引いている。** 手で書き写すと必ずずれる

作り置きは記事を読んで書いたものではありません。**誤りが見つかったらこの表を直してください。** 記事から作る問題と違い、根拠が記事にありません。

## 出題の検査

組み上げた設問は、**作り置きも含めて**出す前に全部これを通します。落ちた設問は直さずに捨て、数は他のテンプレで埋めます。

- 選択肢がちょうど4つで、重複していないか
- 正解が選択肢を指しているか
- 問題文に答えが漏れていないか
- 正解だけ長さが浮いていないか（比率と字数の差の両方で見ます。比率だけだと「海女」対「喫茶店の店主」のような普通の組み合わせまで落ちます）
- 作品名そのものが答えになっていないか

テンプレートの取りこぼしは必ず出ます。テンプレ側を全部直そうとするより、最後に一箇所で弾くほうが確実です。

実際、作り置きを書いたときにこの検査が4問を弾きました。正解だけが他の選択肢より極端に長く、**中身を知らなくても形だけで正解が分かる**状態になっていたためです。選択肢の長さを揃えて直しました。

## 記事によっては問題が作れないこと

infobox が無い記事や、各話表の列名が変わっている記事では材料が揃いません。読み込み中に**何が取れて何が取れなかったか**を印で出しているので、原因を追えます。4問も作れない場合はその旨を出して止まります。

材料が足りないテンプレは黙って見送る作りなので、一部が欠けても残りで出題は成立します。

## 公開

GitHub Pages に置く場合、`apps/day05-dramaou/` がそのまま URL になります。

```
https://ainaraomakaseare-coder.github.io/my-app/apps/day05-dramaou/
```

Artifact として公開すると CSP が外部通信を全部止めるため、**この作りでは動きません**。問題を取りに行けなくなります。

## テスト

```
node test/quiz.test.js     # 文字列の整形・出題の組み立て・設問の検査・採点（810件）
node test/quiz.ui.js       # 実ブラウザでの画面の流れとパーサ（117件、要 playwright）
```

`quiz.test.js` は `index.html` の `PURE-BEGIN` から `PURE-END` までを切り出して node 上で直接動かします。この範囲は DOM にも通信にも触れないので、そのまま試験台に載せられます。

`quiz.ui.js` は Wikipedia への通信を差し替えるので、**ネットにつながっていなくても走ります**。実際の記事に近い HTML を食わせて infobox と各話表の読み取りを見るほか、地の文から3種類の出題が実際に出ること、そして**書体の読み込み以外に外へ通信していないこと**まで見ています。
