# ベイ日記

NPB12球団に対応した個人用の観戦日記・成績分析アプリ。HTML1枚で動き、ビルドもサーバーも要りません。

```
open index.html
```

## できること

- 球場に行った日ごとに、対戦相手・スコア・勝敗・球場を記録
- 同行者、チケット代、天気・気温、写真を添えて記録
- 自分なりのMVP選手や、興奮したこと・印象に残ったシーンをメモ
- ホーム：応援球団の今シーズン・全年度通算・直近6試合の観戦成績
- 成績分析：応援球団と年度で絞り込み、年度別・月別・球場別を比較
- チームの年間成績（勝・敗・分）を球団×年度で手入力し、観戦勝率との差をポイント表示
- 球団変更後も過去の試合は記録時の球団を保持（従来の記録はDeNAとして移行）
- 観戦した試合でよく名前を挙げた選手を「選手分析」画面でランキング表示（MVP=2pt、その他の活躍=1ptで集計）
- データはすべてこの端末のブラウザ内（localStorage・IndexedDB）に保存。設定画面から丸ごとJSONで書き出し・読み込みができ、機種変更のときも安心

## 試合結果の自動取得について（現在は非表示）

試合結果APIの取得ボタンとAPIキー設定欄は非表示にしています。以下は将来再開する場合の参考情報です。過去メモを読み取るOpenAI機能とは別です。

対戦相手やスコアを手入力する代わりに、設定画面で [api-sports.io](https://api-sports.io/) の無料APIキーを登録すると「試合結果をAPIから取得」ボタンで自動入力を試せます。ただしNPBの公式データを網羅した安定・無料のAPIは今のところ見当たらず、この機能は**試験的なベストエフォート**です。

実際にAPI-BASEBALLの無料プランで検証したところ、2つの制限があることが分かりました。

1. チーム情報（`/teams`）は2022〜2024年シーズンのデータにしかアクセスできない（`Free plans do not have access to this season, try from 2022 to 2024.`）
2. **試合結果（`/games`）は、さらに厳しく実行日の前後数日程度にしかアクセスできない**（例：`Free plans do not have access to this date, try from 2026-09-15 to 2026-09-17.`のように、当日を挟んだごく短い範囲しか許可されない）

2番目の制限により、**「後から過去の観戦記録をつける」というベイ日記の使い方には、この無料プランはほぼ対応していません**。試合直後（数日以内）に記録する場合は使える可能性がありますが、基本的には手入力を前提に運用してください（キーを登録しなくてもアプリの他の機能はすべて使えます）。有料プランであれば制限が緩和される可能性があります。

```
node test/logic.test.js   # 勝敗判定・年度集計・選手分析ロジック
node test/ui.smoke.js     # 実ブラウザでの記録・編集・削除・写真添付の流れ（要 playwright）
```

## 集計とプラン

- 勝率は勝 ÷（勝＋敗）。引き分け・結果未設定は分母から除外し、勝敗がない場合は「—」。観戦数には結果未設定も含みます。
- 今季は端末の暦年。直近6試合は選択球団・全年度の結果確定済み記録を日付の新しい順に表示し、未来日を除きます。6件未満は実際の件数を表示します。
- 球場名は前後の空白を除いた入力値で集計。未入力は「球場未設定」。異なる表記・旧名称は自動統合しません。
- ホームと成績分析は球団別、試合記録・選手分析は全球団の記録が対象です。年度別表は通算とすべての記録年度、月別・球場別は選択年度です。
- チーム成績は手入力で、自動更新されません。観戦勝率との差は因果関係を表しません。
- 無料：観戦記録、写真、今季・通算・直近6試合。Plus候補：年度別比較、月別、球場別、チーム比較。今回はすべて無料で利用可能で、決済・価格・実際のアクセス制限は未実装です。
- 有料化する際は認証・決済・サーバー側の利用権検証が必要です。localStorageのフラグを課金判定に使わないでください。
- 保存キーと写真DBは従来どおりです。新しい比較成績は settings.actualRecords[teamId][year] に保存し、JSONバックアップにも含みます。
- 既存の記録を引き継ぐには同じブラウザ・同じ公開URLで利用するか、旧版の設定からJSONを書き出し、新版で読み込んでください。別URLのプレビューに既存データが自動で移ることはありません。

## 追加の検証

PlaywrightをNodeから解決できる環境で実行してください。特定Linuxパスへの依存をなくしました。

```sh
node test/logic.test.js
node test/ui.smoke.js
node test/analytics.ui.js
```

インストール済みEdgeで検証する場合は環境変数 PLAYWRIGHT_CHANNEL=msedge を指定できます。BAYDIARY_QA_DIR を指定すると、分析テストが1280px・390pxの画面画像を保存します。テスト用データは独立したブラウザコンテキスト内だけに作成します。

## 結果共有

ホームと成績分析の「結果を共有」から、応援球団・年度別／直近6試合／全年度通算／球場別を選択できます。1080×1350のPNGに勝率・観戦数・勝敗・アプリ名・呼びかけを掲載し、画像保存と投稿文コピーを提供します。ファイル共有に対応したブラウザではOSの共有メニューを開き、未対応なら画像保存へ進みます。投稿自体はユーザーが共有先で行います。写真・同行者・個人メモは共有画像に含めません。

公開URLが決まったらサーバーの `PUBLIC_APP_URL` にHTTPSのアプリ紹介／App Store URLを設定すると、画像と投稿文へ反映します。HTML単体では `meta[name="baydiary-public-url"]` を設定できます。未設定時に架空のストアURLやlocalhostを掲載することはありません。

## 過去メモからの一括登録

ホームまたは試合記録の「メモから一括登録」を開きます。

1. テキストを貼り付けるか、UTF-8の `.txt` / `.md` / `.csv` を複数選択（合計3万文字、ファイル合計120KB以内）。画像・PDF・Wordの直接読取はこの版では未対応です。
2. 記載がない場合の応援球団を指定。年のない日付を補う年度は任意で指定します。年を指定しなければ日付不明として確認を求めます。
3. AIで読み取り、JSONを確認・修正します。別のAIに渡せる変換用プロンプトのコピー、JSONファイルの読込・保存にも対応。
4. 「取込内容を確認」で行ごとの問題を表示。日付・得点などが不正な行は修正が必要です。同日・同球団・同じ相手は重複候補として初期選択を外します（ダブルヘッダーなど別試合なら明示的に選択可能）。
5. 選択した記録だけを追加します。従来のバックアップ復元と異なり、既存の記録・設定・写真を置換しません。元メモを `sourceMemo` として保存し、試合カードとJSONバックアップで確認できます。

AIは読み誤ることがあるため、登録前に内容を確認してください。AI読取は最大100試合、JSON直接取込は最大500試合です。保存に失敗した場合は既存状態を変更せず、編集したJSONを保存して再試行できます。

## AI接続用サーバー（ローカル開発）

AI変換にはOpenAI APIのサーバー用キーが必要です。HTMLへの埋め込み・ブラウザ保存はしません。

```sh
# apps/day23-baydiary 内で .env.example を .env にコピーし、キーを設定
node --env-file=.env server.cjs
```

Node.js 22以降を想定（追加npm依存なし）。既定は `http://127.0.0.1:60154`。環境変数 `OPENAI_API_KEY`、`OPENAI_MODEL`（既定 `gpt-4o-mini`）、`PORT`、`PUBLIC_APP_URL` が利用可能です。実キーを含む `.env` はGit対象外です。キー未設定でも共有・JSON読込は使えますが、アプリ内のAI変換は接続設定エラーになります。

[OpenAI Structured Outputs公式仕様](https://developers.openai.com/api/docs/guides/structured-outputs)に基づきResponses APIの `text.format` にJSON Schemaを指定。`store:false` でリクエストし、未完了・拒否・通信失敗・利用制限を別扱いにします。メモ本文はAI読取操作時にOpenAIへ送信します。API呼び出しには利用料金が発生し得ます。

このサーバーは開発用のループバック待受限定です。Origin/Hostの検査、本文サイズ制限、タイムアウト、同時実行・回数制限を設けています。一般公開やiOS版の共通バックエンドにする前に、認証・ユーザーごとの利用制限を含む公開サーバー構成を用意してください。

```sh
node --test test/features.test.cjs
node test/features.ui.cjs
```

追加検証はロジック・サーバー15件とブラウザ35件。従来の116件と合わせ166件。OpenAIはモックで契約を検証し、本物のキーによる抽出精度・iOS実機の共有メニューは未検証です。画像とモバイル画面は目視確認済み。

## 大会区分：交流戦・CS・日本シリーズ

試合ごとに `competition` を保存します：`regular`（通常の公式戦）、`interleague`（交流戦）、`cs`（CS）、`japan_series`（日本シリーズ）。区分なしの既存記録は `regular` として移行し、編集画面から変更できます。日付による自動推測はしません。

- ホームの「今季公式戦」は通常の公式戦＋交流戦。交流戦・CS・日本シリーズはそれぞれ独立した枠でも表示します。通算・直近6試合は「全大会」と明示しています。
- 成績分析は球団×年度×大会で絞り込み、年度別・月別・球場別も同じ大会を対象にします。大会別一覧は選択球団・年度の4区分を常に表示し、通常の公式戦と交流戦を重複計上しません。
- 手入力したチームの年間勝率との比較は「公式戦（交流戦含む）」を選んだときだけ表示。CSや日本シリーズの勝率を公式戦全体の勝率と比較しません。
- 試合記録でも大会別に絞り込めます。共有画面は分析の大会選択を引き継ぎ、画像と投稿文に大会名を掲載します。
- AI用JSON Schema・プロンプト・取込確認画面も4区分に対応。区分なしの旧JSONは通常の公式戦として扱う旨を表示し、不正な区分は登録を止めます。
- JSONバックアップにも大会区分を含みます。CS内のファースト／ファイナルの細分化や、オープン戦・オールスターはこの版では未対応です。

大会追加の検証：`node --test test/competition.test.cjs`（6件）、`node test/competition.ui.cjs`（26件）。既存166件と合わせ198件。
