# ベイ日記

NPB12球団に対応した個人用の観戦日記・成績分析アプリ。HTML1枚で動き、ビルドもサーバーも要りません。

```
open index.html
```

## できること

- 球場に行った日ごとに、対戦相手・スコア・勝敗・球場を記録
- 同行者、チケット代、天気・気温、写真を添えて記録
- 自分なりのMVP選手や、興奮したこと・印象に残ったシーンをメモ
- ホーム：応援球団の今シーズン・全年度通算・直近6試合の観戦成績
- 成績分析：応援球団と年度で絞り込み、年度別・月別・球場別を比較
- チームの年間成績（勝・敗・分）を球団×年度で手入力し、観戦勝率との差をポイント表示
- 球団変更後も過去の試合は記録時の球団を保持（従来の記録はDeNAとして移行）
- 観戦した試合でよく名前を挙げた選手を「選手分析」画面でランキング表示（MVP=2pt、その他の活躍=1ptで集計）
- データはすべてこの端末のブラウザ内（localStorage・IndexedDB）に保存。設定画面から丸ごとJSONで書き出し・読み込みができ、機種変更のときも安心

## 試合結果の自動取得について

対戦相手やスコアを手入力する代わりに、設定画面で [api-sports.io](https://api-sports.io/) の無料APIキーを登録すると「試合結果をAPIから取得」ボタンで自動入力を試せます。ただしNPBの公式データを網羅した安定・無料のAPIは今のところ見当たらず、この機能は**試験的なベストエフォート**です。

実際にAPI-BASEBALLの無料プランで検証したところ、2つの制限があることが分かりました。

1. チーム情報（`/teams`）は2022〜2024年シーズンのデータにしかアクセスできない（`Free plans do not have access to this season, try from 2022 to 2024.`）
2. **試合結果（`/games`）は、さらに厳しく実行日の前後数日程度にしかアクセスできない**（例：`Free plans do not have access to this date, try from 2026-09-15 to 2026-09-17.`のように、当日を挟んだごく短い範囲しか許可されない）

2番目の制限により、**「後から過去の観戦記録をつける」というベイ日記の使い方には、この無料プランはほぼ対応していません**。試合直後（数日以内）に記録する場合は使える可能性がありますが、基本的には手入力を前提に運用してください（キーを登録しなくてもアプリの他の機能はすべて使えます）。有料プランであれば制限が緩和される可能性があります。

## 集計とプラン

- 勝率は勝 ÷（勝＋敗）。引き分け・結果未設定は分母から除外し、勝敗がない場合は「—」。観戦数には結果未設定も含みます。
- 今季は端末の暦年。直近6試合は選択球団・全年度の結果確定済み記録を日付の新しい順に表示し、未来日を除きます。6件未満は実際の件数を表示します。
- 球場名は前後の空白を除いた入力値で集計。未入力は「球場未設定」。異なる表記・旧名称は自動統合しません。
- ホームと成績分析は球団別、試合記録・選手分析は全球団の記録が対象です。年度別表は通算とすべての記録年度、月別・球場別は選択年度です。
- チーム成績は手入力で、自動更新されません。観戦勝率との差は因果関係を表しません。
- 無料：観戦記録、写真、今季・通算・直近6試合。Plus候補：年度別比較、月別、球場別、チーム比較。今回はすべて無料で利用可能で、決済・価格・実際のアクセス制限は未実装です。
- 有料化する際は認証・決済・サーバー側の利用権検証が必要です。localStorageのフラグを課金判定に使わないでください。
- 保存キーと写真DBは従来どおりです。新しい比較成績は settings.actualRecords[teamId][year] に保存し、JSONバックアップにも含みます。
- 既存の記録を引き継ぐには同じブラウザ・同じ公開URLで利用するか、旧版の設定からJSONを書き出し、新版で読み込んでください。別URLのプレビューに既存データが自動で移ることはありません。

## 追加の検証

PlaywrightをNodeから解決できる環境で実行してください。特定Linuxパスへの依存をなくしました。

```sh
node test/logic.test.js
node test/ui.smoke.js
node test/analytics.ui.js
```

インストール済みEdgeで検証する場合は環境変数 PLAYWRIGHT_CHANNEL=msedge を指定できます。BAYDIARY_QA_DIR を指定すると、分析テストが1280px・390pxの画面画像を保存します。テスト用データは独立したブラウザコンテキスト内だけに作成します。
