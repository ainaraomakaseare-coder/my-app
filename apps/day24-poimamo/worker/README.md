# ポイまも AI Worker

Anthropic（Claude）のAPIキーをブラウザに公開せず、スクリーンショット画像（1枚〜最大6枚）から「サービス名」と「内訳（期間限定ポイントの複数のロット＋通常ポイント）」を読み取って返すCloudflare Workerです。楽天ポイントのように、1つのサービスが失効日の異なる複数の期間限定ポイントと通常ポイントを同時に持つ実態に合わせ、内訳は配列（`lots`）で返します。内訳が多くて1枚の画面に収まらない場合は、スクロールしながら複数枚のスクショを撮って一度にまとめて読み取らせることもできます（`images`配列で複数枚渡す）。DAY05のドラマ検定・DAY18のおもいでWikiと同じ構成ですが、個人のポイント画面という機微な画像を扱うため**キャッシュはしません**（レート制限のみ）。

**公開URLは `https://poimamo-ai.hiroya-apps.workers.dev` です（2026-09-18 公開）。** `../index.html` の `poimamo-ai-endpoint` メタタグに設定済みです。ご自身の端末（PowerShell）から`npx wrangler login`でCloudflareにログインし、`wrangler secret put`・`wrangler deploy`を実行して公開しました（Claude Codeのクラウドセッションにはデプロイ権限が無いため、手順のみ用意してユーザー側で実行した形です）。

以下は再デプロイ・別アカウントでの公開時の手順です。

## 公開

```sh
cd apps/day24-poimamo/worker
npx wrangler secret put ANTHROPIC_API_KEY
npx wrangler deploy
```

Anthropicの[コンソール](https://console.anthropic.com/)で発行したAPIキーを`ANTHROPIC_API_KEY`として登録します。DAY05・DAY18はOpenAIのキーでしたが、こちらはAnthropic（Claude）のキーが必要です（別のキーです）。

公開できたら、公開されたURL（`https://poimamo-ai.<あなたのサブドメイン>.workers.dev` の形）を `../index.html` の `poimamo-ai-endpoint` メタタグの `content` に設定してください。**空のままなら、スクショ読み取り機能はアプリ側で自動的に無効化され、手入力だけで使えます。**

`wrangler.jsonc` の `ratelimits[0].namespace_id`（`72400`）は、Cloudflareアカウント内で他のWorkerのレート制限と重複しない適当な数字であれば構いません。既に別のWorkerで同じ番号を使っている場合はデプロイ時にエラーになるので、その場合は別の番号に変更してください。

## 費用について

1回の読み取りごとに、画像1枚分の入力トークンと数百トークン程度の出力の料金がかかります（モデルは既定で費用の低いClaude Haiku 4.5）。個人の利用であれば1回あたりごくわずかですが、**費用が発生する機能である**ことは着手前に伝えたとおりです。心配な場合は`wrangler.jsonc`の`ratelimits`で回数制限をさらに絞ってください。

## 読み取りの作り方

「AIに自由に読み取らせて自然文で返す」のではなく、Anthropicのtool use（`extract_point_info`という名前の構造化ツール）を使い、`program`・`lots`（`pointType`・`balance`・`expiryDate`・`expiryMonth`を持つ内訳の配列）・`confidence`だけを固定フォーマットで返させています。画面に複数の期限違いの期間限定ポイントや、期間限定と通常の両方が表示されている場合は、見えている内訳を1つも欠かさず`lots`にすべて含めるようプロンプトで指示しています（優先して1件だけ選ばせるのではなく、全件を返させる設計です）。失効月ごとに何行も並んでいる画面でも省略・要約させず、月だけの場合は `expiryDate: null` と `expiryMonth`（年が確定すれば `YYYY-MM`、不明なら `MM`）を返します。月末はアプリで計算し、年不明の場合は月を表示して日付の補完を求めます。AIには現在年や翌年を推測させません。

「通算ポイント」「累計獲得ポイント」のような、今使える残高ではなく過去の実績値を示すだけの数値は`lots`に含めないよう明示しています（これらは失効管理の対象外のため）。

画像に書かれた文字列が指示文のように見えても、それに従わずデータとしてのみ扱うよう明示しています（スクリーンショットという外部由来の内容を鵜呑みにしないため）。

AIの読み取り結果は、アプリ側で必ず編集可能な一覧として表示し、ユーザーが確認・修正してから確定する設計です（Workerも、呼び出し元のアプリ側も、読み取り結果を自動で保存することはありません）。サービスの詳細画面から「スクショで情報を更新する」を使った場合、確定した内容はそのサービスの内訳を丸ごと置き換えます（新しく別のサービスを登録する場合は内訳を1件追加するだけです）。

APIキーは`wrangler.jsonc`の通常変数へ書かず、必ず`ANTHROPIC_API_KEY`をsecretとして登録してください。

出力上限は4096トークンです。上限到達で途中になった応答や内訳配列のない応答は502として返し、不完全な内訳での置き換えを防ぎます。月別抽出の変更を有効にするには、フロントエンドの公開とWorkerの再デプロイが両方必要です。

## 合計の二重計上防止

AIは合計（totalBalance）、明記された通常（regularBalance）、期間限定小計（limitedBalance）、期限別内訳（lots）を分けて読み取ります。合計1000pt・期間限定200ptなら通常800ptとしてコード側で計算します。通常が明記されていればその数値を使い、さらに期間限定を引くことはありません。合計と内訳の矛盾、小計と月別行の不一致、通常を計算するための内訳不足は422（inconsistent_balances）で返し、画像の追加や手入力を案内します。

既に保存したデータは自動変更しません。重複登録があるサービスの詳細画面から「スクショで情報を更新する」で読み取り直し、確認して更新してください。

## 単位と通常残高の期限（カレンダー対応）

抽出に `unit`（pt/マイル）、`pageKind`、`regularExpiryDate`、`regularExpiryMonth` を追加しました。`lots` は通常・期間限定のどちらの期限別内訳も受け入れます。通常合計から既存の通常内訳を引いた残りだけを追加し、ANAの通常マイル小計を重複させません。通常全体に期限が明記されている場合も保持します。

`pageKind` が付与予定のみなら `scheduled_only`、異なるサービスの混在なら `mixed_services`、残高の画面でなければ `unsupported_screen` を422で返します。最短期限だけの期間限定小計は全額の期限として扱わず、詳細内訳を求めます。

利用可能残高と運用込みの保有残高が両方ある場合は利用可能残高を対象とします。通常の期限が無いことと、画面から確認できないことを同一視して期限を推測しません。画像認識後のデータをモックしたテストで検証しており、有料の実画像API呼び出しは行っていません。
