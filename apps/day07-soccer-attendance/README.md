# サッカー出欠管理

チームの出欠を、スプレッドシートの代わりに管理するアプリ。マネージャーが予定を登録し、メンバーは**LINEで配られた自分専用のリンク**を開いて出席か欠席かを1タップで答えます。

**入力した内容はデータベース（Supabase）に残ります。**アプリを閉じても、別の端末から開いても消えません。

```
予定をつくる  →  LINEで個人リンクを配る  →  各自が1タップで回答
                                          ↓
                           出席人数と「未回答の人」が一覧で見える
```

## 画面は2つ

| ファイル | 誰が使う | 開き方 |
|---|---|---|
| `index.html` | メンバー | `.../#<個人トークン>` |
| `admin.html` | マネージャー | `.../admin.html#<管理トークン>` |

**ログイン画面はありません。リンクそのものが鍵**です。LINEでURLを踏んだ人は、そのまま自分の欄だけ触れます。メールを送る必要がなく、LINEに貼るだけで配れます。

> Googleログインは採用していません。**LINEの内蔵ブラウザはGoogleのOAuthを弾く**ため（`403: disallowed_useragent`）、LINEで配る運用と噛み合わないからです。

## できること

- メンバーの登録（スプレッドシートの名前をそのまま貼り付けて一括登録）・背番号・休会
- 試合／練習の予定登録（日付・開始時刻・場所・メモ）
- メンバーが出席／欠席を1タップで回答。もう一度押すと未回答に戻る
- 出席人数・欠席人数・未回答人数の自動集計と、**未回答者の名前一覧**（LINEで催促する相手がそのまま分かる）
- 誰が来るかをメンバー側からも確認できる
- マネージャーによる代理入力（LINEで個別に返事が来たとき用）
- 個人リンクの作り直し（漏れたときに古いリンクを無効化）

## 準備

### 1. データベースを作る

Supabase でプロジェクトを作り、**SQL Editor** に `db/schema.sql` の中身を丸ごと貼って Run します。実行の最後に**管理用トークン**（32文字）が出るので控えてください。管理画面の鍵です。

見失っても `select admin_token from team_config;` で取り直せます。

### 2. 接続先を書く

`index.html` と `admin.html` の先頭にある meta タグを埋めます。

```html
<meta name="soccer-supabase-url" content="https://xxxxxxxx.supabase.co">
<meta name="soccer-supabase-key" content="sb_publishable_...">
```

値は Supabase の **Settings → Data API** の Project URL と、**Settings → API Keys** の Publishable key（`sb_publishable_…`）です。

- URL の末尾に `/rest/v1/` が付いていても動きます（自動で外します）
- **Secret key（`sb_secret_…` / `service_role`）は絶対に書かないでください。**このアプリは一切使いません

## キーが公開されて平気な理由

publishable キーは Supabase が「ブラウザに配る前提」で作っているキーです。Supabase の管理画面にもこう書かれています。

> This key is safe to use in a browser **if you have enabled Row Level Security (RLS) for your tables**

守っているのはキーの秘密ではなく、**データベース側の鍵**です。`db/schema.sql` は全テーブルで RLS を有効にし、**許可ルールをひとつも書いていません**。つまりキーを持っていてもテーブルは何ひとつ読めず、書けません。

読み書きはすべて `db/schema.sql` の後半にある**関数だけを窓口**にして通ります。関数は毎回トークンを確かめてから動きます。だから、

- リンクを持っていない人 → 何も見えない
- 自分のリンクを持っている人 → **自分の欄だけ**動かせる
- 管理トークンを持っている人 → 名簿と予定を触れる

**これは想像ではなく、テストで確かめています。**`test/db.test.sql` の14〜17番は、わざと anon にテーブルの読み書き権限を全部与えた上で、それでも1行も読めず1行も書けないことを確認します。RLS を切ると、そのテストはその場で落ちます。

リンクが漏れたときは、管理画面の**リンク配布**タブで「作り直す」を押してください。古いリンクはその場で使えなくなります。

## テスト

```
psql -v ON_ERROR_STOP=1 -d <データベース> -f test/db.test.sql   # 関数の動きと鍵のかかり具合（17項目）
node test/fake-supabase.js &                                    # Supabase の代役（手元の PostgreSQL に繋ぐ）
node test/ui.smoke.js                                           # 実ブラウザでの流れ（要 playwright）
```

`test/fake-supabase.js` はテスト専用です。本番では使いません。画面のテストは、**回答したあと閉じて開き直しても残っていること**と、**別の端末から開いても残っていること**まで確かめます。

## いま出来ないこと

- 出欠は「出席・欠席・未回答」の3つだけ。「未定」「遅刻」は入れていません
- ログインが無いため、リンクを他人に転送されるとその人になりすませます。チームLINEの中で配る前提の作りです
- 無料プランの Supabase は**1週間アクセスが無いとプロジェクトが一時停止**します。データは消えず、管理画面のワンクリックで戻ります
